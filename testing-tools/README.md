# 测试工具

此目录保存长期维护的自动验证程序，禁止存放媒体素材、固定参考数据正文、下载缓存、运行日志和一次性实验。

| 内容 | 职责 |
| --- | --- |
| 根目录 `*.test.mjs` | 产品与测试协议的自动断言 |
| `helpers/` | 媒体生成、服务启动、记录协议、独立参考读取等共用代码 |
| `tools/` | 提交规范、平台归档、清理策略的专项检查及参考生成工具 |
| `coverage.json` | 功能与产品测试用例的映射 |
| `fixtures.lock.json` | 固定输入的不可变来源 URL、精确字节数和 SHA-256；不包含素材正文 |
| `prepare-fixtures.mjs` | 下载缺失固定输入并校验缓存 |

执行入口和通过条件以 [测试规范](../docs/testing.md) 为准。`npm test` 仍是标准命令，由 `scripts/test.mjs` 调度此目录中的程序。固定输入保存在 `.build/testing-fixtures/<清单摘要>/`；测试生成文件写入当前隔离源码工作区内的 `.build/testing-work/`。直接执行单个用例时，相同相对路径位于当前工作目录。

`npm run test:prepare` 可在联网时预先取得全部固定输入；缺失文件会按锁定提交下载，已存在文件也须通过长度和摘要检查。首次迁移固定到本仓库已有提交的历史快照，以保持原有字节和来源信息。后续输入变更必须审核新来源和摘要，禁止用产品输出刷新参考答案。缓存损坏会明确失败；核对后只移走相应缓存文件，再重新准备。清理缓存后需要重新下载。

SI/TI 的固定输入包含上游 siti-tools 0.6.0 源码、五个原始片段、对应发布结果和许可证，以及独立参考矩阵。`layout-oracle.json.gz` 覆盖 150 种整数像素布局、全/有限范围及三种尺寸，共 900 例。142 种布局来自 libavutil 描述符的已知字节，8 种较新高位对齐布局经过 FFmpeg 往返验证；期望值使用独立二维卷积和总体标准差计算。它们与产品代码分别维护，普通回归重放冻结输入。`tools/generate-siti-reference.py` 的新输出仅写入 `.build/generated-siti-reference/`，不会覆盖锁定缓存。

根目录旧 `test-work/` 是兼容保留位置，包含受保护的历史验收资料，不再承接这些用例的新输出。正式测试记录与中断恢复资料按 [数据与归档](../docs/data-and-archives.md) 单独管理。

重复帧的 `repeat-qualification.test.mjs` 随通用回归执行：锁定 NIST SHA-256 原始向量和 FFmpeg n8.1.3 原始 FATE 定义/答案；对实际运行时接受的布局集合逐项核对官方原生输出或明确的可逆表示关系；每分量遍历全部有效码值，并验证完整边缘块及 CSV 字节边界。固定上游输入与许可证只在经摘要校验的 `.build` 缓存中保存，不随应用分发。官方参考向量和项目控制输入分开记录，不构成机构认证。

`node testing-tools/repeat-resource.mjs` 另做昂贵的完整资源资格检查；参数 `boundary` 单独检查重复分析自身的两百万帧、超限和取消，`long` 单独检查30分钟1080p120及10分钟4K120。独立父进程计时并采样实际 Node/FFmpeg/FFprobe 内存；采样峰值是下界，不是所有机器的性能保证。

[哈希研究审计](tools/hash-audit.md)由 `tools/hash-audit.mjs` 显式执行：NIST 字节型 SHA-256/SHA-512/SHA3-256 向量、实际 OpenCL GPU、CPU 指令能力屏蔽及并行、受控媒体的 CUDA 解码/布局/时间/颜色解释，以及分开计时的哈希性能。它不改变生产哈希算法、不提供机构认证，也不替代通用或 GPU 发布门槛；依赖、范围与重现步骤见工具说明。所有输入、编译产物和结果留在项目 `.build/`。

[完整文件 CPU/GPU 分析对照](tools/whole-file-gpu-audit.md)另验证批量原生摘要、直接比较、逐分量差异、持久参考静止筛查及原始 PTS 的完整结果：对照现有产品、单次读取 CPU 与两块实际 GPU 的软件/硬件解码路径。独立资格检查逐字节比较完整软硬解输出，并对新内核重放官方 SHA-256 消息和阈值算术边界。研究后端不接入生产分析，端到端、初始化、传输与独立解码基线分开记录。

[CPU/GPU 并行分担完整帧哈希](tools/cooperative-gpu-audit.md)在独立证据目录对照 CPU 分担 0/25/50/75/100% 的完整帧 SHA-256，GPU 保留全部样本差异与静止筛查；另验证新增 Windows CNG CPU 提供者和实际并发观察。它只扩展研究工具，不更换生产算法，不把多块摘要拼接当成标准 SHA-256。
