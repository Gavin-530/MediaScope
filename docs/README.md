## 维护约定

- 同一规则在上表指定的文档中维护，其他文档引用它。正式文档描述当前行为，不能依赖本机计划或会话背景才能使用。
- 尚未实现的方案、实施流水和历史安排放在 `local-notes/`；已确认且仍生效的规则须整理进正式文档，并核对代码和验证依据。历史计划中的约束不因存放目录自动失效。
- 正式文档不保存历次正文、迁移回执或某次测试通过数。工具版本、格式版本、限制和必要的旧格式兼容说明继续保留。
- 命令、路径、行为或格式改变时，同时更新正文、入口链接及读取这些文档的工具。功能尚未提交时，不单独推送声称该功能已存在的文档。
- `local-notes/` 整根 Git 忽略且受清理保护，需要单独备份。计划名用 `主题-plan-YYYYMMDDTHHmmssZ.md`，操作回执用 `主题-receipt-YYYYMMDDTHHmmssZ.md`，按实际保存时间命名，日期和时间以 `T` 分隔，时区统一为 UTC，末尾 `Z` 标明 UTC；不使用双连字符或修订序号。同主题同一秒需要保留多份时，秒的小数部分以点分隔，毫秒格式为 `HHmmss.fffZ`，禁止覆盖已有文件。历史资料沿用有依据的时间和精度，未知时分秒不补造；文件名时间的依据及被替代关系写入正文或清单。
- 本地索引指出当前有效计划；需要保留的旧版冻结，新修订另存。上游参考资料按来源和版本保存，不作为运行依赖。归档中的离线 README 是随资料携带的使用说明，不能作为第二份独立维护的项目规范。
