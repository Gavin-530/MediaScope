# 项目文档

此目录只维护当前生效的项目说明和规则，与对应代码一起审查、提交和推送。每个主题保留一份正文，历史由 Git 提交和标签保存。

| 文档 | 唯一主要职责 |
| --- | --- |
| [贡献规范](contributing.md) | 提交说明、作者、PR 和审阅 |
| [测试规范](testing.md) | 本地与 GitHub 测试、覆盖和通过条件 |
| [发布规范](releasing.md) | 版本、附件、发布步骤和说明 |
| [数据与归档](local-data.md) | 用户数据、目录保护、测试证据、平台档案和恢复 |

## 维护约定

- 同一规则在上表指定的文档中维护，其他文档引用它。正式文档描述当前行为，不能依赖本机计划或会话背景才能使用。
- 尚未实现的方案、实施流水和历史安排放在 `local-notes/`；已确认且仍生效的规则须整理进正式文档，并核对代码和验证依据。历史计划中的约束不因存放目录自动失效。
- 正式文档不保存历次正文、迁移回执或某次测试通过数。工具版本、格式版本、限制和必要的旧格式兼容说明继续保留。
- 命令、路径、行为或格式改变时，同时更新正文、入口链接及读取这些文档的工具。功能尚未提交时，不单独推送声称该功能已存在的文档。
- `local-notes/` 整根 Git 忽略且受清理保护，需要单独备份。计划名用 `主题-plan--YYYY-MM-DD--rNNN.md`，修订号在同一主题内持续递增；操作回执用 `主题-receipt--YYYY-MM-DD[_HHmmss]--NN.md`。时间未知时不补造，正文注明时区、状态、依据及被替代关系。
- 本地索引指出当前有效计划；需要保留的旧版冻结，新修订另存。上游参考资料按来源和版本保存，不作为运行依赖。归档中的离线 README 是随资料携带的使用说明，不能作为第二份独立维护的项目规范。
