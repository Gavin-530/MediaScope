# SI/TI 计算依据

新计算采用固定 [VQEG/siti-tools 0.6.0，c537e33793266187aad87c859fd62a9de9033854](https://github.com/VQEG/siti-tools/blob/c537e33793266187aad87c859fd62a9de9033854/src/siti_tools/siti.py) 的完整 PQ 数学流程。参考源码 SHA-256 为 `84557e030e302fa14e28a1cd1227f3320986050c4cf5f5f4d590215971329873`。报告标识为 `VQEG-siti-tools-0.6.0-PQ-v1`，配置版本 8。

目标是在相同亮度样本、位深、范围、传递函数、显示参数和场景下与指定版本数值一致。P.910（10/2023）是参考软件引用的标准，指定版本兼容不构成 ITU 官方认证，也不证明严格符合 P.910 或其最新修订。上游 HLG 公式存在已知分段跳变；本方法保留该行为，不替换公式后仍宣称与原版等价。

## 固定流程

1. FFmpeg 软件解码原尺寸、原格式画面，不自动旋转、缩放、抽帧或转换色彩。缺少亮度范围、传递函数时由用户核实确认。
2. YUV／灰度读取原生亮度；RGB 按明确的 BT.601／709／2020 非恒定亮度权重导出非线性亮度，不先量化为整数 Y。布局、RGB、灰度和不透明 Alpha 为软件输入适配，不等同于原版 CLI 的文件读取支持。
3. 全范围为 code/(2^b−1)；有限范围按 8/10/12-bit 的 16–235、64–940、256–3760 归一化。9/14/16-bit 按整数端点关系扩展，并在报告 inputAdapter 标记，不声称原版构造器直接支持这些位深。
4. SDR 按归一化 BT.1886 EOTF（gamma=2.4、黑白0/1）后仿射映射到 300/0.1 cd/m²；逆 sRGB 使用上游分段后同样映射到 300/0.1。随后使用原版 PQ OETF。不能将其描述为直接将物理黑白位代入完整 BT.1886 reference EOTF。
5. HLG 默认峰值1000、黑位0.01 cd/m²。gamma 在峰值≤1000时为1.2，否则1.2+0.42×log10(峰值/1000)。逆映射低段 V²/3，高段 exp((V−1.00429347)/0.17883277)−0.02372241；再以(峰值−黑位)×linear^gamma+黑位映射，编码PQ。保持上游分段行为。PQ 输入归一化后保持 PQ。
6. SI 为 Sobel 梯度幅值的总体标准差，剔除一像素边界；TI 为相邻帧差的总体标准差。两者**所有位深固定乘255**，保留未舍入值。场景首帧 TI 为 null，不纳入统计。
7. 确认场景时逐场景统计并排除跨场景 TI。未确认时保留全片参考并提示可能包含剪辑点。比较需要相同分辨率、帧率、显示假设与处理条件。

有限范围外样本继续拒算，这与固定上游的输入策略一致，不代表所有正常有损视频都只含标称黑白区间内的值。不自动裁剪或改判为全范围。输入错误须返回明确原因并关闭解码及计算管道，其他分析继续；取消不触发重试。

## 输入和执行支持

保留已识别 8/9/10/12/14/16-bit 整数 YUV／灰度／RGB 布局、大小端、NV/P0xx/P2xx/P4xx、GBR、打包RGB与完全不透明 Alpha。格式识别在 public/siti.js。浮点、未知布局、半透明等缺少输入约定时明确不可算。隔行须明确选择 BWDIF 每帧输出一帧；原生格式不被滤镜支持时拒算，不隐式转格式。

文件能否处理取决于 FFmpeg 是否能解封装、软件解码，以及实际解码像素格式和色彩声明是否满足上述条件；文件扩展名不是支持判据。识别一种原始帧布局、验证这种布局的计算，以及验证实际封装文件的完整处理，是三种不同证据，不能互相代替。格式清单应与实际运行时的 `ffprobe -show_pixel_formats` 交集核对，不能把正则可匹配的名称全部算作实际存在的格式。

## 工程限制与硬件范围

有限范围外样本当前一律拒绝，这是软件输入策略，不是标准要求所有样本只在标称黑白区间内；正常有损编码也可能触发。帧校验失败时取消相关计算并继续排空已解除管道连接的解码输出，避免等待子进程关闭时停滞。

单帧宽高至少3，像素总数最多35,389,440；最多2,000,000帧、2,048个已确认场景。上限属于软件资源和结果规模策略，最小尺寸来自当前只计算Sobel内部区域的实现。CPU不足60帧时串行；并行度上限8，还受帧数、可用CPU和内存预算约束。这些均不是ITU规定的文件格式或硬件要求。

CPU 串行／并行和 GPU 采用同一方法。CPU 保留双精度参考，帧并行共用一次软件解码，小块帧携带准确前帧；GPU 接收原生帧，使用一条通用FP32指标管线。非PQ整数亮度使用主机双精度前处理表舍入到FP32，RGB按共享参数前处理：HLG RGB保留GPU双精度亮度与完整传递函数分段，其他RGB在GPU进行FP32前处理；原生PQ亮度以精确整数码值表示，统计后由主机双精度换算至固定255尺度。Sobel、TI和总体方差使用FP32。设备执行故障才按原配置从首帧回退CPU，不拼接部分GPU结果；共同输入/解码/一致性错误直接结束该项，取消不重算。

固定上游HLG在0.5存在不连续，不能用FP32亮度舍入决定RGB输入分支。HLG RGB在支持cl_khr_fp64且具备次正规数、Inf/NaN及最近偶数舍入的GPU上以双精度计算完整前处理，随后将实际PQ工作面舍入并写入同一FP32指标管线；GPU仍验证原生字节，报告明确preprocessingDevice为gpu。没有改变HLG公式、扩大容差或增加精度菜单。新增已知字节临界矩阵分别用独立固定公式、二维卷积及CPU参考核对，并回读参与计算的真实GPU工作面；0–1 PQ样本的绝对误差上界2^-24用于覆盖FP32存储舍入及更小的FP64传递函数误差，不能用最终指标容差代替。

GPU负责SI/TI计算，视频仍软件解码；当前不使用CUDA、硬件视频解码或多GPU分担，需要Windows OpenCL 1.2、FP32非规格化数/Inf-NaN/就近舍入和256线程工作组，检查各内核上限、总内存和单次分配；仅HLG RGB另需上述FP64能力，均不接受基本运算的软件模拟，不启用fast-math。默认优先选择满足上述FP64能力的首个GPU，否则选择首个合格FP32 GPU，并进行实际输入自检；助手可选设备序号用于资格复核，界面不增加精度菜单。共享内存GPU的缓冲计入主机预算。平台、后端和精度门槛是工程选择。某块GPU的实测结果只证明该设备和驱动，其他设备仍须执行同样验收。HLG峰值设置须大于0且不超过10,000 cd/m²，黑位须非负且小于峰值；这是本配置的参数范围，不是文件读取规范。

原生PQ归一化为`(code−lo)/(hi−lo)`。Sobel对常量的响应为零，`std(aX+b)=|a|std(X)`；因此先用`code−lo`计算Sobel/TI及标准差，再乘`255/(hi−lo)`，数学定义和边界不变。16位及以下码值、相邻差及Sobel分量均能由FP32精确表示，幅值和方差仍有舍入。方差先减去数组首个实际样本，再进行两遍中心化和分组求和，使常量数组严格为零，不设置小值清零阈值。这一表示变换不用于非线性SDR/sRGB/HLG前处理。

GPU 编译采用短文件名，旁存完整源码 SHA-256 核对缓存身份，临时文件独立命名，避免把完整哈希和 UUID 叠加到深路径。保留会话和缓冲复用、空闲60秒释放、丢失后重建；运行代码更新后须重启应用。测试使用独立源码副本、随机端口和数据目录，不干扰用户当前实例。

主要计算代码为四个文件：`siti.mjs`（解码／调度／工作进程）、`public/siti.js`（输入／计算／验证）、`gpu/SitiOpenCl.cs`（GPU 指标）、`gpu/siti-opencl.ps1`（系统桥接）。无需 Python 运行依赖。显示帧和像素边界共用于 `public/analysis-limits.js`，C# 后端保留相同常量并由协议与真实画面测试核对。

## 资源边界与报告

单轨最多 2,000,000 个显示帧；总像素最多 35,389,440，宽高至少为 3，覆盖 8192×4320 与其竖屏形式，不强制长宽比。这些是工程边界，不是 P.910 阈值，也不代表最大分辨率与最大帧数的全部组合已经验证。位深、布局、范围、传递函数、Alpha、隔行、场景及时间戳的既有条件继续适用，计算配置版本为 8。场景数仍最多 2048。

CPU/GPU 继续执行主机内存预算检查；GPU 额外检查设备总内存与单次分配上限，仍以实际分配和数值自检为准。扫描及码流解析每 16,384 条检查 Node 堆使用量是否超过堆上限的 85%，或系统空闲内存是否少于 64 MiB；触发时明确失败，不提供完整结论。这只是保守保护，不能保证消除所有内存不足。

完整分析的详细码流头解析独立保留 500,000 包、750,000 AV1 事件预算，数量不按显示帧比例推算。达到任一预算后，该项标为 resource-limited，不发布截断列表和全流依赖结论；保留解码器关键帧区间，其他分析独立继续。解码错误、取消和共同数据错误仍按原规则处理。

报告接口与用户主动导出使用统一 [JSON 0.5 开发草案](json-format.md)，读取兼容0.4，逐帧数值、配置和证据保持完整；导入导出上限为 256 MB。结果仅保留在本次服务的内存中，长期保存需主动导出 JSON。提高计算准入帧数不保证最大帧数报告能导出或重新导入；导入与导出仍构造完整 JSON 字符串及对象，内存和运行时字符串长度可能先成为限制。

边界验证包括真实 8192×4320 两帧解析图样、真实 8×8 的 2,000,000 帧图样；GPU 的最大帧数协议检查与实际完整帧运行证据须分开解释。计算边界测试不代表最大报告的保存、导入或导出验证。没有运行 8192×4320 × 2,000,000 帧的最大组合，不据此推断通用吞吐率或所有 GPU 型号的能力。

SI/TI 描述内容复杂度，不是质量评分或剩余压缩率。固定工具兼容、扩展输入支持和标准符合性是分别验证的目标。

## 固定兼容方法的验收条件

以下条件共同判定当前声明范围内的计算正确性，全部通过即验收通过。发布目录是否已切换到该源码版本单独核对摘要，不与计算正确性混为同一结论。

| 验收项 | 必须通过的检查 |
| --- | --- |
| 原版共同输入 | 同一解码亮度样本、设置和场景，未经修改的固定0.6.0原版函数/CLI、原始发布文件结果与产品逐帧SI/TI及统计相符；原版发布数据及源码摘要不可随产品重写。 |
| 扩展输入适配 | 对已声明的布局与归一化约定，独立已知字节精确还原样本，覆盖通道、位深、端点、大小端、有效位、Alpha及奇数尺寸；PQ域下双精度读取器逐样本误差不超过5e−16，用于验证输入适配；最终SI/TI符合下述上游数值比较规则。其他传递域由固定原版参考矩阵约束。GPU实际工作缓冲另行回读：PQ亮度逐码值精确一致；PQ RGB按12次FP32舍入的前向误差界核对，不能以未参与计算的旁路代替实际缓冲。 |
| CPU/GPU执行 | CPU串行/并行逐帧一致；真实GPU执行与原版及独立参考相符，不能以CPU回退、跳过或只做设备探测代替。时间戳、场景首帧、前帧衔接及取消/故障恢复均须通过。 |
| 文件入口 | 有效封装素材实际解码布局、亮度样本和时间戳保持一致；不支持或标记错误的输入必须明确拒算，不能输出猜测值。无效测试素材单独记录，不能当成计算失败或有效格式正例。 |

最终SI/TI数值比较采用固定 [siti-tools 0.6.0上游测试 test/test.py](https://github.com/VQEG/siti-tools/blob/c537e33793266187aad87c859fd62a9de9033854/test/test.py#L475) 实际执行的 `pytest.approx(value, rel=0.005, abs=0.01) == ground_truth`。对有限数值，规则为 `|实测−参考| ≤ max(0.01, 0.005×|实测|)`：绝对容差与相对容差取较宽者，不相加；相对项以传入approx的实测值为基准，保持上游调用方向。CPU/GPU结果、独立指标参考、解析指标边界和GPU数值自检使用同一规则；新GPU报告记录来源、两项容差、max规则及实测值基准。发布验收逐帧重核CPU/GPU数值，不以单个最大绝对误差代替相对容差判断。
