# SI/TI 计算依据与分阶段实现

固定目标为 ITU-T P.910（10/2023），只涉及 SI/TI 条款，不声明实现整份主观视频评价建议书。历史 `P910-2023-SDR-BT1886-text-v1` 的数学口径保持不变。2026-10-13 扩展了原生 YUV/灰度、明确输入解释、HLG 显示模型、显式 PQ 保留解释及 BWDIF，随后按用户确认增加 RGB 分数亮度、明确语义的 32-bit 浮点、大小端/半平面和独立范围/尺度参考配置，再新增显式物理亮度及透明 RGB 合成。CPU 串行、帧级并行和 OpenCL 双精度 GPU 使用同一配置，支持已确认场景。所有新结果明确记录标准解释疑点；功能扩展不能消除标准文字歧义，也不等于完整严格合规或官方认证。

## 正文与参考实现的差异

VQEG 是重要的参考实现，但不能把其默认参数等同于 ITU 的全部规定。固定 v0.3.0 的 SDR 默认黑位为 0.1 cd/m²；其 display model 使用归一化 gamma 曲线后再做仿射亮度映射；输出固定乘 255。本配置分别采用 P.910 B.2 的 0.01、BT.1886 Annex 1 的含黑位参考 EOTF，以及 P.910 7.8.1.5 的输入位深乘数。因此不预期与 VQEG 默认整条流水线逐值相同，也不会以偏差放宽方式掩盖这些差异。

P.910 7.8.1.5 方程使用输入位深 b，但随后的文字称不同位深可在同一尺度比较；固定 VQEG 代码则明确采用 255。这一差异不能由本软件假装已经消除。原文配置继续使用输入位深乘数并将其保存，禁止宣传不同位深输出可直接比较。初期 v1 未增加固定 255 选项；2026-10-13 用户随后明确授权增加独立范围/尺度参考配置，见下文，它不改写原文配置，也不被称作 ITU 对原文的修正。

VQEG 后续确认了 10-bit 有限范围中 `16/255` 与 `64/1023` 的差异，并于 2025-06-29 合并修正，提交 `1e0675510b053418e6751f843cd1fb5afc5ca07f`。[原始讨论](https://github.com/VQEG/siti-tools/issues/25)、[修正 PR](https://github.com/VQEG/siti-tools/pull/26)。这是参考实现的修正，不能直接当作 ITU 对 10/2023 的官方勘误。当前 v1 配置仍固定原文比例，明确记录这一差异；本次执行方式迁移不改变其数学含义。不能仅凭对照通过，宣称上述解释争议已经解决或所有结果均符合唯一官方口径。

验证采用独立 Python/NumPy 的正文公式预处理，再调用固定 VQEG 的原始 Sobel、TI、PQ 数学函数生成约定测试向量；源文件摘要与取用函数都可核查，不改写参考函数。该验证证明已声明配置的实现对应关系，不等于 ITU 合规认证。工程数值比较阈值必须单独标明，不能称为 ITU 官方误差容限。

## 按标准核查后的决定（2026-10-11）

- 黑位 0.01 cd/m²、白位 300 cd/m²：B.2 有明确参数，继续使用，不改用 VQEG 默认黑位 0.1。
- 有限范围：继续执行 7.8.1.2 的显式 8-bit 比例；BT.1886 的原生 10-bit 黑白码值与后续 VQEG 修正不能悄然覆盖该配置。公开 ITU 版本目录本次未列出 10/2023 的单独勘误，不能将参考项目修正标为 ITU 勘误。
- SDR EOTF：保留已声明的 BT.1886 Annex 1 参考方程。BT.1886 Appendix 1 讨论该方程并另外提供可选 CRT 近似；P.910 B.2 指向 Appendix 1，不能据此声称 Annex 1 是唯一指定方程，也不任意改用缺少本项目测量参数的 CRT 近似。报告保存具体选择和标准文件摘要。
- 越界输入：P.910 7.8.1 没有独立指定这些样本应裁剪、外推还是拒绝。当前确定保留保守拒绝策略，明确标为软件输入政策，不虚称标准要求拒绝，也不自动改变素材。
- HDR（当时 v1 的边界）：7.8.1.3 将 PQ 分支写成恒等映射，但 7.8.1.4 又将物理亮度送入 PQ 逆 EOTF；VQEG 的 HDR10 分支直接保留 PQ 值。HLG 引用 BT.2100-2 Table 5，其 EOTF 还涉及显示峰值、黑位和系统 gamma；P.910 B.2 未像 SDR 那样指定统一的 HDR 参数。不能把参考默认值当作 P.910 强制参数，或将有歧义的 PQ 串联解释声称为唯一标准口径。2026-10-13 的独立配置和用户确认见下文。

这些决定固定软件行为与可复现依据，不构成对标准文字矛盾的正式解释。更广泛的格式、HDR 解释和其他品牌 GPU 的硬件验收仍是独立后续工作；GPU 与 CPU 逐值完全一致已按用户要求移出待办。

## 已确认场景的计算与保存

界面提供“边界未确认（全片参考）”“已确认只有一个场景”“按已确认边界分场景”。输入各场景起始显示帧，从 1 计数并包含 1，例如 `1, 101, 251`。API、任务计划与报告以从 0 计数的 `sitiSceneStarts: [0, 100, 250]` 保存；必须严格递增且小于实际帧数，最多 2048 个场景。选择分场景表示用户确认已列出全部边界，软件不声称自动核实该声明。

CPU 与 GPU 在各场景首帧重置时间差计算，只用该场景的后续相邻帧产生 TI。CPU 并行将全局场景起始帧转换到每段局部帧序号，前置重叠帧仍保持原有作用，不被额外算入汇总。单帧场景的 TI 统计为 null；单场景的 SI/TI 与原有全片值相同；多场景仅提供各场景统计和原时间轴曲线，不提供混合全片均值。

新报告的 `sceneAnalysis` 记录边界是否确认，`scenes` 保存各场景的帧范围、首末 PTS 和未舍入统计。导入时核对边界、逐帧 TI 空值、帧数、时间戳和统计；历史报告仍按其原结构读取，不回写或推断剪辑点。

7.8.5 提到用历史 TI 移动平均检测可能剪辑点，但窗口和阈值需经验确定，且对交叉淡化可能不可靠。当前不制造“官方阈值”，不将关键帧或 TI 峰值自动当作已确认边界。缺少确认时仍可查看全片参考，其状态始终保留。

## 输入与执行边界

历史 v1 仅自动选择明确 BT.709、tv/pc、原生 YUV 420/422 8/10-bit。扩展配置接受明确 SDR 标签 BT.709、SMPTE 170M/240M、BT.2020-10/12，并统一选择已声明 BT.1886 显示模型；HLG 按标签进入显示模型配置。缺少范围或无法解释的传递函数，必须由用户明确选择才进入扩展配置。PQ 必须显式选择“保留 PQ 的参考解释”。隔行须显式选择 BWDIF；声明未知时仍核对实际输出逐行状态。未获所需解释时，原有 420/422 8/10-bit 输入仍可产生明确标注的旧流程参考；其他格式返回不可用。若用户已要求新版解释或已确认场景，条件不足直接报错，禁止用旧流程替代。

新配置严格拒绝超出输入声明合法亮度码值的帧（有限范围 8-bit 16–235、10-bit 64–940；全范围对应原位深）；这是软件的保守输入政策，不是 P.910 明文要求拒绝。不自动裁剪、不把有限范围重新认定为全范围。BT.1886 的 `max(V+b,0)` 属于其方程本身；没有另加预处理裁剪。

软件解码后将原生 Y 平面流入独立计算子进程，源视频无需写出中间文件。CPU 使用 Float64 查找表和两遍总体方差；独立进程保持界面响应并支持取消。

CPU 默认最多 4 路，按帧数、逻辑处理器和可用内存预算自动限制，少于 60 帧或没有完整帧扫描时保持串行。每段从头按显示顺序软件解码，不跳转；非首段包含前一帧，确保段首 TI 使用正确相邻帧，合并时丢弃重复的前置帧。各段逐帧核对预扫描，合并再核对全部帧及重叠帧 SI/PTS。任一段失败先结束所有子进程，再尝试串行；取消不重试。报告保存实际路数、请求上限和回退原因。

GPU 使用 Windows OpenCL 1.2、`cl_khr_fp64`、256 大小工作组及足够设备内存；驱动需能编译内核并通过每次任务的数值自检。自动使用首个具有双精度扩展的 GPU；无法执行时丢弃 GPU 结果，回退同配置 CPU。软件解码后输出原位深亮度；CPU 按 `2**b` 个码值建立双精度预处理表并发送，非法码值位置保留 NaN。C# 独立核对 SDR/PQ/HLG 公式与参数，GPU 执行双精度 Sobel、帧差和两遍总体方差。未启用 fast-math，禁止 FP contraction，不把中间值降为 float，不把输出舍入到两位小数。GPU 的归约顺序与串行 Kahan 求和不同，不承诺逐位一致。

GPU 自检比较独立 C# 标量 Sobel/方差，真实硬件验收另逐帧比较串行 CPU 和独立 NumPy 参考。工程阈值为 `1e-8 + 1e-10 * abs(reference)`，用于未舍入 SI/TI 及汇总；不是 ITU 容差、认证或对所有硬件/输入的误差保证。验收包括两种位深、两种范围、420/422、奇数尺寸、1080p/4K、VFR/7200 秒起始时间，以及帧数、时间戳、尺寸、非法码值和取消检查。CPU 分段验收比较未舍入逐帧值与汇总，要求与串行逐值相同；场景验收还覆盖与 CPU 分段相邻/重合的边界、连续边界、单帧场景和 GPU 场景重置。

没有新增应用运行依赖或捆绑 GPU 库。沿用 Node.js、FFmpeg、Windows PowerShell/.NET 和显卡驱动中的 OpenCL；只增加桥接及计算源码。测试参考使用的 Python/NumPy/SciPy 不随软件分发。

历史 v1 不覆盖 HDR 及扩展输入；v2 扩展配置仍限定原生平面亮度。后续 v3 从已列明的原始分量布局计算，并保存矩阵与浮点假设；不支持的布局仍拒绝处理。无法解释的 Log、线性与绝对亮度不会自动归为 SDR。后续标准或参考实现升级必须建立新配置版本并重做对照，不能改写历史报告的计算依据。

用户已确认 HLG 默认显示模型为峰值 1000 cd/m²、黑位 0.01 cd/m²、系统 gamma 1.2；这些值是软件采用的显示假设，不是 P.910 统一强制值。界面选择 HLG 后可修改三项参数，API 与任务计划用 `sitiSettings.hlg` 保存。报告记录实际参数及来源：项目已确认假设或用户输入。

HLG 黑位提升 `beta=sqrt(3*(Lb/Lw)**(1/gamma))`，对非彩色亮度信号计算 `s=max((1-beta)*V+beta,0)`；逆 OETF 使用分段 `s²/3` 或 `(exp((s-c)/a)+b)/12`，其中 `a=0.17883277,b=1-4a,c=0.5-a*ln(4a)`；物理亮度 `L=Lw*linear**gamma`。该选择明确按 P.910 的标量亮度平面使用 HLG，不能声称与针对完整 RGB 的显示还原逐像素等价。

去隔行需要用户显式选择 `sitiSettings.interlaced='bwdif'`，实际滤镜为 `bwdif=mode=send_frame:parity=auto:deint=interlaced`，每个输入帧输出一个逐行帧，自动读源场序。滤镜在分段 select 之前执行，使各段使用完整邻帧；不缩放、不自动旋转、不改变位深。逐帧核对尺寸、格式、实际逐行状态、源时间戳和数量。`preprocessingEvidence` 保存滤镜、输出帧数、时间基、声明输出帧率及按时间戳计算的平均帧率；BWDIF 是用户选择的前处理，不是 P.910 唯一规定。

本节 v2 配置的报告使用 `configurationVersion=2`，保存原始像素格式/范围/传递函数/场序、有效解释、确认来源、显示模型和 `assessment='declared-interpretation'`。`interpretationIssues` 列出范围比例、输出尺度、EOTF、PQ 或去隔行的适用疑点，不能伪造为“严格合规”。导入核对配置、输入解释、数学缩放、参数和前处理证据，并沿用场景/逐帧值/统计校验；历史报告不迁移数值。

独立参考由 `scripts/generate-siti-extended-reference.py` 生成，保留原 SDR 测试向量不变。36 组覆盖 SDR/PQ/HLG、8/9/10/12/14/16-bit 和两种范围，使用独立 NumPy 预处理及固定未改动的 VQEG Sobel/TI/PQ 函数。真实 CPU 对照覆盖灰度/YUV 444、高位深、VFR、场景、其他 SDR 标签、缺失元数据确认、默认/自定义 HLG 参数；去隔行另与独立 FFmpeg 输出亮度逐帧对照并核对串行/并行。真实 GPU 验收额外覆盖 9/12/14/16-bit、PQ/HLG 与独立参考，另对照 SDR/HLG 的 BWDIF 输出及前处理配置，禁止接受 CPU 回退。工程阈值仍为 `1e-8 + 1e-10*abs(reference)`，不代表 ITU 容限。

## 后续 v3：RGB、浮点与范围／尺度参考配置

| 配置 | 与原文配置的关系 |
| --- | --- |
| `P910-2023-reference-255-v1` | 有限范围采用 `(code-16*2**(b-8))/(219*2**(b-8))` 的原位深合法端点；输出固定乘 255。SDR/HLG 显示模型仍用本项目已声明参数，PQ 仍需显式选择保留解释。仅范围和输出尺度参考兼容，不声称与 VQEG 默认整条流程相同 |
| `P910-2023-rgb-text-v1` | 整数 RGB 归一化后导出分数亮度，不经过整数 Y 量化，随后使用原文范围与输出公式 |
| `P910-2023-float-text-v1` | 原始 float32 样本直接提升到双精度，归一化除数为 1，按用户确认的等效位深执行原文范围/输出解释；浮点存储位数 32 不作为公式中的 b |
| `P910-2023-native-storage-text-v1` | 从扩展原始 YUV/灰度布局读取亮度，包含大端与半平面有效位解析，原文数学口径不变 |

RGB 支持 GBR 平面 8/9/10/12/14/16-bit 和 float32、RGB/BGR 24/48-bit、常见 32/64-bit RGB 透明或填充布局；透明通道须每个样本完全不透明，拒绝猜测背景或预乘语义。YUV/灰度支持原有平面、相应大小端和已列明的 MSB 存储；半平面包括 NV12/NV21/NV16/NV24/NV42 和 P010/P012/P016、对应 422/444 的 P2xx/P4xx。布局由 `public/siti-formats.js` 显式识别，不泛化到任意 FFmpeg 格式；填充位非零的有效位布局保守拒绝。所有输入保持原尺寸/位深，不进行 FFmpeg 自动颜色转换。去隔行仍须显式选择 BWDIF，且滤镜须支持该原始格式；不为满足滤镜偷偷量化或转换浮点/RGB。

RGB 的非线性亮度权重为 BT.601 `(0.299,0.587,0.114)`、BT.709 `(0.2126,0.7152,0.0722)`、BT.2020 非恒定亮度 `(0.2627,0.6780,0.0593)`。一致的矩阵或色原色声明可作为依据；缺失、不支持或互相冲突的声明须用户明确输入。常量亮度 BT.2020 和 ICtCp 等不自动按该加权式解释。BT.709 3.2/3.5 定义非线性亮度和数字量化关系；本配置明确选择不先执行整数 Y 量化，是用户确认的输入解释，不能声称为 P.910 唯一规定。[BT.709-6](https://www.itu.int/rec/R-REC-BT.709-6-201506-I/en)、[BT.2100-2](https://www.itu.int/rec/R-REC-BT.2100-2-201807-S/en)。每帧继续核对源矩阵/色原色、范围、传递函数与轨道声明及帧间变化。

API/计划参数为 `sitiSettings.scale`（`literal` 或 `reference-255`）、`matrix`（`auto`、`bt601`、`bt709`、`bt2020`）、`floatEncoding='normalized-nonlinear'` 和 `floatDepth`（8/9/10/12/14/16）。浮点有限范围的输入合法端点按等效位深归一化并取 float32 可表示端点，拒绝非有限/越界样本，不裁剪；后续计算使用原始 float32 精确提升后的值。原文输出采用 `2**floatDepth-1`，参考配置采用 255；所有浮点等效位深均明确标为假设。

v3 报告保存 `configurationVersion=3`、原始格式布局/标签、范围/尺度选择、矩阵权重和来源、浮点假设、完整预处理与输出公式。导入核对配置、数学参数与源报告的一致性；新配置删除版本字段或更改权重/尺度也会拒绝。v1/v2 历史报告继续按原口径验证，不重写历史测量值。统一 255 只解决显示尺度，不保证任意不同素材或量化精度逐值相等；比较还须同矩阵、域、显示模型、分辨率、帧率与场景条件。

CPU 从原始分量计算 float64 PQ 平面；GPU 路径由独立 CPU 子进程执行相同 float64 前处理，向 OpenCL 发送未舍入 double 平面，GPU 计算 Sobel/TI/两遍总体方差。报告明确记录 `float64 host preprocessing; fp64 GPU metrics`，不声称 RGB/浮点前处理在显卡上执行。GPU 自检独立核对 C# 标量指标，CPU/GPU 均保留取消与完整帧数/源时间戳校验。

新增独立 NumPy 参考 `scripts/generate-siti-input-reference.py` / `test/reference/siti/p910-2023-inputs.json`，覆盖 40 组 RGB/灰度、大小端、透明/填充、半平面、float32（含有限范围端点）、SDR/PQ/HLG 和两种范围/尺度配置，不改写旧向量。实际 CPU 验收覆盖原始 RGB/浮点/大端/NV12、VFR、串行/并行和场景；灰度浮点另外使用无损 float EXR，避免原始 NUT 缺少该像素格式标签而产生错误解码。P010/P016 等布局目前由直接原始样本向量验证，未以错误容器标签冒充真实解码验收。真实 GPU 另逐帧对照 6 类输入的 CPU 与 NumPy，必须使用 GPU，禁止以回退通过。API、队列计划、浏览器和报告往返均验证新参数及配置完整性；工程阈值沿用 `1e-8 + 1e-10*abs(reference)`。

## 后续 v4：显式物理亮度与透明 RGB

2026-10-13 用户确认新增归一化线性光、绝对亮度浮点和线性光域 Alpha 合成。历史默认与 v1/v2/v3 数值、模型、报告不迁移。新增配置必须显式选择，不根据 EXR、浮点存储或 Alpha 标签自动猜测语义，也不将新前处理称作 P.910 唯一规定。

| 配置 | 输入解释及流程 |
| --- | --- |
| `P910-2023-linear-light-float-v1` | `floatEncoding='normalized-linear'`，原生 float32 必须在 0–1，用户输入 `linearDisplay={blackCdM2,whiteCdM2}`；用 `L=Lb+(Lw-Lb)*x` 映射显示光，再对线性 RGB 导出亮度并编码 PQ。不是场景光，不再执行 SDR/HLG EOTF |
| `P910-2023-absolute-light-float-v1` | `floatEncoding='absolute-cdm2'`，原生 float32 按显示亮度 cd/m² 解释，必须在 0–10000；对线性 RGB 导出亮度后直接 PQ 编码，不归一到假定峰值、不再次执行 EOTF |
| `P910-2023-linear-alpha-v1` | RGB 的 `alpha={mode,backgroundCdM2:[R,G,B]}` 必须明确填写；先在输入信号域按需解除预乘，再转换成显示线性 RGB，执行不透明背景上的 source-over，导出线性亮度后编码 PQ |

物理浮点仍要求 `floatDepth`（8/9/10/12/14/16），只用于已声明输出尺度假设；必须显式输入 `range='pc'`，不把 cd/m² 或线性光误当作有限范围整数码值。归一化线性光的黑位与峰值无默认：`0 <= Lb < Lw <= 10000`。物理浮点的 `transfer` 可省略或为 `auto`，拒绝另外指定 SDR/PQ/HLG、HLG 参数或 PQ 保留选项，避免重复处理。范围、单位、映射、源标签和用户确认来源均保存。

透明合成仅扩展明确识别的 RGB Alpha 布局（RGBA/BGRA/ARGB/ABGR、64-bit、GBRA 整数及 float32）；YUV Alpha 仍只接受完全不透明样本，不猜测色度重建。Alpha 必须是 0–1 的线性覆盖率，独立于 RGB 范围/单位。背景三个分量是源 RGB 色原色下的显示线性光，单位 cd/m²，每个值必须在 0–10000；不得把非线性 sRGB 数值或其他色原色的背景直接填入。背景 Alpha 固定为 1。

`mode='straight'` 表示直通颜色；`mode='premultiplied-signal'` 精确限定为输入信号域关联：非线性输入先按原位深合法端点展开范围后关联，物理输入按 0–1 或 cd/m² 原单位关联。预乘源颜色须满足 `stored <= alpha*maximum`；有限范围和浮点关联上限按原存储精度舍入，只有这些可表示端点解除关联时允许极小的端点回落，不进行一般越界裁剪。`alpha=0` 的预乘源须有零关联颜色，拒绝无法解释的隐藏分量。直通源的零 Alpha 颜色不影响合成，但源样本仍须有限且在已声明域内。先解除预乘、再执行 EOTF；不将“在线性光域预乘后再编码到非线性信号”自动等同于这个约定。

透明非线性 RGB 的有限范围采用原位深合法端点（浮点端点先取 float32 可表示值），由独立物理配置决定，不能被原文 16/255 比例覆盖。SDR 分量各自使用已声明 BT.1886 Annex 1；PQ 分量各自使用 BT.2100-2 Table 4 EOTF；HLG 分量先黑位提升、逆 OETF，再用 `Ys=sum(weight*sceneRGB)`、`displayRGB=Lw*Ys**(gamma-1)*sceneRGB` 执行亮度相关 OOTF。使用已记录的矩阵权重，颜色与显示模型属于显式输入假设。完整 RGB HLG 与旧非彩色标量模型保持独立。[BT.2100-2 Table 4/5](https://www.itu.int/rec/R-REC-BT.2100-2-201807-S/en)。

显示线性 RGB 按 `Cout=alpha*Csource+(1-alpha)*Cbackground` 合成，再按矩阵导出亮度 `Y`，最后以 PQ 逆 EOTF 编码 `Y`；没有在 PQ 或其他非线性码值域合成。source-over 代数可对照 [W3C Compositing and Blending Level 1 §9.1.4](https://www.w3.org/TR/compositing-1/#porterduffcompositingoperators_srcover)，线性显示光、背景单位与源解释是本项目已确认的独立模型，并非 P.910 针对透明媒体给出了这些唯一参数。选择原文尺度时仍乘 `2**b-1`，选择 `reference-255` 时乘 255；两者都属于独立物理配置，不能因此把整条新前处理标成原文配置，也不保证不同配置可直接比较。

报告 `configurationVersion=4` 保存 `physicalLight`、`alphaComposition`、线性矩阵来源与权重、EOTF/亮度映射及输出公式。导入重新从源声明及设置推导配置，拒绝单位、背景、Alpha 模式、显示参数、权重、EOTF、输出尺度或版本被破坏的报告。API/计划使用上述 `sitiSettings` 字段，界面输入条件相同；物理浮点会禁用不适用的传递函数输入，黑位/峰值/背景均要求填写。

CPU 串行与帧级并行使用相同 float64 原生分量前处理。GPU 对 v4 接收主机生成的未舍入 PQ double 平面，桥接 `RawMode=2` 不再读取不适用的整数 LUT；自检仍独立核对 C# 标量 Sobel/TI 与两遍方差。设备实际分工、取消、场景重置、源帧数/格式/时间戳完整性及回退策略沿用既有路径。

独立参考 `scripts/generate-siti-physical-reference.py` / `test/reference/siti/p910-2023-physical.json` 新增 80 组向量，覆盖两种输出尺度、归一化线性/绝对亮度、SDR/PQ/HLG、直通/预乘、零 Alpha、部分覆盖率、非零有色背景、大小端和 float32 实际存储精度。预处理由独立 NumPy 完成，PQ/Sobel/TI 使用固定未改动 VQEG 函数，不改写旧向量。真实 CPU 和 GPU 各覆盖 8 类原生解码输入（灰度 float32 用无损 EXR/Matroska 保留完整序列），CPU 另核对 VFR/分段并行/场景；GPU 必须实际使用显卡，逐帧对照 CPU 与 NumPy。API、浏览器、队列计划和报告往返核对实际参数及破坏拒绝。工程阈值仍为 `1e-8+1e-10*abs(reference)`，不是 ITU 容限。
