# SI/TI 计算依据

参考 [ITU-T P.910（10/2023）§7.8.1–7.8.7、Annex B](https://www.itu.int/rec/T-REC-P.910-202310-S/en)，按下列实施解释计算。当前尚未完成该标准的严格符合性确认；本页记录实际计算方法及待核清的规范对应问题。只运行 PQ 域流程，主输出采用输入整数位深倍率；不再运行旧 FFmpeg 编码值域或软件自定义物理光／Alpha 合成流程。主观实验的素材集合设计、受试者与评分流程不属于本工具的计算范围。

Sobel/TI 核参考源码固定为 [VQEG/siti-tools c537e33793266187aad87c859fd62a9de9033854](https://github.com/VQEG/siti-tools/blob/c537e33793266187aad87c859fd62a9de9033854/src/siti_tools/siti.py)，SHA-256 为 `84557e030e302fa14e28a1cd1227f3320986050c4cf5f5f4d590215971329873`。显示模型、范围和尺度由独立公式验证。新报告使用 `P910-2023-PQ-v1`、配置版本 7，保存参考版本、输入依据、显示参数、解释标识、实际倍率和执行设备。参考一致性不等于 ITU 官方认证；不把推荐参数称为标准强制要求。

HLG 前处理采用 P.910 附录 B.2 指定的 [BT.2100-2 表 5](https://www.itu.int/dms_pubrec/itu-r/rec/bt/R-REC-BT.2100-2-201807-S!!PDF-E.pdf)，高段逆 OETF 使用加号，并在输入侧应用黑位抬升，不沿用固定 VQEG 源码的高段减号与输出侧仿射黑位映射。

## 固定计算步骤

1. FFmpeg 软件解码原尺寸画面，禁止自动色彩转换、旋转、缩放和抽帧；读取明确的格式、范围及传递函数。声明缺失时需用户核实后确认。
2. YUV／灰度读取原生亮度；RGB 按明确的 BT.601、BT.709 或 BT.2020 非恒定亮度权重导出非线性亮度，不先量化到整数 Y。
3. 全范围归一化到 0–1；有限范围以输入位深的合法亮度端点归一化：`16×2^(b−8)` 至 `235×2^(b−8)`。超出声明范围则拒绝该项 SI/TI，不猜测范围或裁剪数据。
4. SDR 使用完整 BT.1886 reference EOTF，默认黑位 0.01、峰值 300 cd/m²；逆 sRGB 使用所选参考显示模型（黑位 0.2、峰值 80 cd/m²），再编码 PQ。HLG 使用 BT.2100-2 表 5 的输入侧 β 黑位抬升、逆 OETF 和 OOTF，默认黑位 0.01、峰值 1000 cd/m²。gamma 在 400–2000 cd/m² 按注释 5f 推导，范围外采用其脚注 2 的扩展公式；PQ 输入归一化后保持 PQ。
5. SI 为 Sobel 梯度幅值的总体标准差，排除一像素边界；TI 为相邻帧亮度差的总体标准差。两者均乘 `2^b−1`，b 为输入整数位深；8/10/12/16-bit 倍率分别为 255/1023/4095/65535，保留未舍入数值。跨位深原始输出不直接混比。
6. 场景首帧 TI 未定义，保存为 null，不纳入汇总。确认多场景时逐场景统计并排除跨场景差分；未确认边界时明确标注全片参考。推荐的场景均值与辅助 P95／最大值分别展示。

BT.1886 使用 [2011 版 Annex 1](https://www.itu.int/dms_pubrec/itu-r/rec/bt/R-REC-BT.1886-0-201103-I!!PDF-E.pdf) 的完整参考 EOTF：`gamma=2.4`，`A=(Lw^(1/gamma)−Lb^(1/gamma))^gamma`，`B=Lb^(1/gamma)/(Lw^(1/gamma)−Lb^(1/gamma))`，`L=A×max(V+B,0)^gamma`。采用 P.910 B.2 推荐的 Lw=300、Lb=0.01 cd/m²。

逆 sRGB 分段为 `V/12.92`（V≤0.04045），否则为 `((V+0.055)/1.055)^2.4`；物理亮度映射 `L=0.2+79.8×linear`。80/0.2 cd/m² 来源于 [ICC 的 sRGB 编码登记及参考显示说明](https://registry.color.org/rgb-registry/srgb)，这是本实现选定的参考显示模型，不是 P.910 对所有 SDR 的强制参数。物理亮度按 BT.2100-2 表 4 编码 PQ。

## 原文解释与条款对应

| 条款 | 本实现的固定处理与解释 |
| --- | --- |
| §7.8.1.1/.2 | 全范围 `code/(2^b−1)`；有限范围 `(code−16×2^(b−8))/(219×2^(b−8))`。原文固定 16/255、235/255 按 8-bit 示例扩展，与高位深逐字代入不同；采用实际整数标称黑白点及 BT.1886 的 10-bit `(D−64)/876` 映射。 |
| §7.8.1.3/.4、B.2 | SDR/HLG 映射物理亮度后编码 PQ；B.2 的 BT.1886 定位写为 Appendix 1，本实现选择 Annex 1 reference EOTF，明确保留定位差异。PQ 输入的恒等分支按已在目标域解释，不再次按物理亮度编码。 |
| §7.8.1.5 | 按 `2^b−1` 输出，b 解释为输入整数位深；这与固定 VQEG 的 255 以及原文“same scale”的概括存在语义分歧，报告记录实际倍率。 |
| §7.8.2/.3、B.1 | Sobel 梯度幅值、排除一像素边界、总体标准差；相邻帧差；场景首帧 TI 为 null。 |
| §7.8.4/.5 | 均值为主汇总，每场景 N 个 SI、N−1 个 TI；确认边界时不算跨场景 TI。未确认边界时保留全片参考与限制提示。 |
| §7.8.6/.7 | 比较须保持分辨率、帧率和处理条件一致，不自动重采样或抽帧。 |

范围扩展、BT.1886 引用定位、PQ 衔接及输出尺度的规范对应仍待核清。列明解释和通过数值测试不构成这些解释符合标准的证明；当前结果不应直接标作已验证的 P.910 标准测量结果。P.910 建议有剪辑点时按场景处理，也允许无法分离等情况下跨场景计算；未确认边界的全片结果须按此限制解释。

版本 5（`VQEG-siti-c537e337-PQ`）和版本 6（`P910-HLG-BT2100-2-PQ-v1`，HLG 修正）报告保留原配置、原值与固定 255 倍率，均标注“历史计算口径”。更早报告也保留原口径；不重新计算、改倍率或改显示参数。历史任务重新执行生成版本 7 新报告，不能改写原报告；旧自定义倍率、浮点等效位深或合成设置须重新选择。

## 格式与执行方式

支持 8／9／10／12／14／16-bit 的已识别整数 YUV／灰度／RGB 布局，包含常见平面、大小端、半平面 NV／P0xx／P2xx／P4xx、RGB／BGR／GBR 及完全不透明的 Alpha。格式描述集中于 `public/siti.js`。

VQEG 原始输入范围表直接列出 8／10／12-bit；9／14／16-bit 使用整数码值关系扩展端点。RGB 权重与存储布局适配属于本软件的输入支持，不能声称 VQEG 上游直接测试了每一种容器或布局，也不属于 P.910 对所有 RGB 格式的官方认证。

浮点亮度、半透明内容、未知布局、未知传递函数、冲突且未确认的 RGB 矩阵等缺少依据时，SI/TI 返回明确的不可计算原因，其他媒体分析继续。隔行输入须明确选择 BWDIF 每帧输出一帧；滤镜不支持原生格式时拒绝该项，不偷偷转格式。

有限范围外样本当前一律拒绝，这是软件输入策略，不是标准要求所有样本只在标称黑白区间内；正常有损编码也可能触发。此类输入错误还存在解码管道收尾可能停滞的已知问题。

CPU 串行／并行及 GPU 共用输入解释、样本布局、显示参数和双精度计算模型。整数 YUV／灰度用同一函数生成 PQ 查表：CPU 逐样本查表，GPU 接收原生帧并查同一张双精度表。RGB 也直接传送原生帧，由 GPU 按共享配置给出的亮度权重、范围端点、显示参数和传递函数常数计算双精度 PQ，再计算指标；不再传送整幅主机 Float64 PQ 平面。GPU 数学后端按独立参考及 CPU 验证，不新增计算口径、不插值、不量化。Sobel、帧差和两遍总体方差仍为 fp64；场景首帧跳过无定义的 TI 统计。

CPU 串行与并行均只执行一次 SI/TI 软件解码。并行按小块连续帧轮流分发：亮度输入每块 8 帧；RGB 根据帧数与工作进程数均衡分配，每块最多 16 帧。每块额外携带准确的前一帧用于 TI，块内复用已完成的前处理。队列按工作进程数限制内存，避免逐帧配对重复 RGB 传递函数计算；保持 TI 与串行完全一致，不重新计算上一帧 SI，也不从头反复解码分段前缀。去隔行在这条完整解码流中执行，保留邻帧上下文；核对完整帧数、顺序及源 PTS。工作进程执行故障可回退串行；明确的共同输入、解码或一致性错误不重复计算。输入解码线程在 `-i` 前明确设置，rawvideo 输出线程独立固定为 1；CPU 工作进程数与解码线程数分别记录。

GPU 需要 Windows 和支持 fp64 的 OpenCL GPU。首次使用按 C# 源码哈希编译临时可执行程序，同一应用进程复用一个 GPU 工作进程、OpenCL 上下文和可复用缓冲；每次设置实际输入仍执行数值自检。空闲 60 秒或应用退出时释放工作进程；没有系统常驻服务或新增安装组件。启动前检查可执行缓存，丢失后自动重建；Windows 权限或锁冲突妨碍稳定文件名发布时，可复用已成功编译的本进程临时文件。运行代码更新后须重新启动应用。

仅设备初始化、后端计算或设备资源故障回退相同配置的 CPU；共同的输入、解码、时间戳或帧数错误直接结束该项 SI/TI，其他媒体分析继续。取消不回退。报告保存每次尝试的设备、帧数、失败阶段、原因和耗时；GPU 上传／计算／回读计时与输入等待分别记录，输入等待与解码有重叠，不能相加推算总耗时。界面允许重新检查 GPU，不永久禁用选择。

HLG 新计算拒绝 β≥1 的反向或恒定映射参数组合；只约束模型有效域，不指定新的显示黑位默认值。历史报告仍按原参数、原值验证并保留，不重新运行。确认单场景时顶层统计复用场景统计。P.910 未规定本项目的进程结构、精度类型、速度、资源预算或工程误差容限。

运行代码只有四个文件：`siti.mjs`（解码／调度／工作进程）、`public/siti.js`（输入／计算／验证）、`gpu/SitiOpenCl.cs`（GPU 指标）、`gpu/siti-opencl.ps1`（系统桥接）。无需 Python 运行依赖。

## 数值验证

测试保留一份固定参考源码、一份参考矩阵和一个生成脚本。`scripts/generate-siti-reference.py` 独立转录原位深范围、完整 BT.1886、逆 sRGB 显示映射、BT.2100-2 HLG/PQ 及输出倍率，只复用未修改的 VQEG SI/TI 核，生成 84 组向量；不导入生产 JS/C# 生成预期值。矩阵还保存改造前冻结的 SDR/sRGB/两种 HLG 配置与测量，用于旧报告验证；原始 VQEG HLG 函数只用于历史样例。黑白点、中间点、分段边界、HLG 显示参数及解析图样分别检查前处理、尺度、总体标准差、场景计数与均值。NumPy／SciPy 只用于开发期重新生成参考矩阵。

CPU／GPU 核对真实解码画面、整数位深、范围、SDR／HDR、RGB、场景及去隔行；GPU 原生帧通道直接核对全部 84 组亮度与 RGB 参考向量，含 P010、大小端、填充位、合法范围及 Alpha，检查截断输入、跨格式上下文复用、缓存重建、共同校验错误不回退和取消恢复；CPU 核对 VFR、准确前帧、一次解码、AVC／HEVC／AV1 和取消。API、报告及浏览器核对设置与数据往返。误差阈值 `1e-8 + 1e-10×|参考值|` 是工程验收阈值，不是 ITU 容限。不能可靠标记部分布局的原始 NUT 文件不作为真实解码证据。

SI/TI 描述内容复杂度，不是质量评分或剩余压缩率。比较仍须相同的显示假设、分辨率、帧率、场景及前处理条件。
