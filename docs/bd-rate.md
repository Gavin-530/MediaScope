# BD-rate 测量规则

依据为 [ITU-T HSTP-VID-WPOM（2020，2025 年修复交叉引用）](https://www.itu.int/dms_pub/itu-t/opb/tut/T-TUT-ASC-2020-HSTP1-PDF-E.pdf)第 7.2–7.4 节，数值参考固定为 JVET-O0003-v1 工作簿 bdrate 与 JVET-T2010-v2 的 Module1。另有同主题的 [ISO/IEC TR 23002-8:2021](https://www.iso.org/standard/81591.html)。这些是测量实践技术文件；软件不声明获得组织认证，也不声称已逐条核验付费 ISO 正文。

## 两种明确分开的口径

默认“参考测量”配置标识为 `itu-sdr-psnr-y-pchip-v1`。使用同一片段各编码点的高精度 PSNR-Y 帧算术均值和基本码流码率，每条曲线至少四点。四点下限是产品的保守策略，不是 BD-rate 数学定义对所有输入的统一限制。现有默认 CRF 设置不变；不足四点明确拒算，用户须增加 CRF。

“探索比较”保留原报告指标：PSNR 使用已有 FFmpeg 全分量 MSE 域汇总；SSIM 变换为 Q = −10·log10(1−SSIM)，要求 0 ≤ SSIM < 1；VMAF 使用同一已记录模型的原始分数。探索码率为视频包平均码率 videoMbps。每组至少两点，两三点显示稀疏提示。这些结果不能改称参考 PSNR-Y 结果。原质量比较、试编码表格、原有图表及 pooled 字段的含义不变。

旧报告缺少新测量字段时，参考模式明确拒算。软件不会从舍入的 psnr_y 日志补造高精度值，也不会静默转用 pooled。用户可以显式选择探索模式。

## 参考测量范围与条款映射

| 依据 | 实现及边界 | 验证入口 |
| --- | --- | --- |
| §7.2 分量 MSE / PSNR | 分别对 Y/U/V 解码整数样本累加逐帧 SSE，再除以各自样本数；峰值为 255 × 2^(位深−8)，10-bit 为 1020 | bd-reference.test.mjs 独立已知像素及 BigInt SSE |
| §7.2 零 MSE | 保留零误差事实，选择文献列举的 HM/VTM 999.99 dB 约定；不是所有实现的唯一约定 | 零误差帧、仅色度变化 |
| §7.3 序列质量 | 分量逐帧 PSNR 的等权算术平均，补偿求和；没有先平均 MSE，也不平均两位小数日志 | 场景误差变化、8/10-bit 与全/限范围 |
| §7.3 序列码率 | 基本码流字节 × 8 × fps / 帧数 / 1000，单位 kbit/s；保存原始字节数、SHA-256、帧率、时长和时间轴核查误差 | 真实三种编码器基本流、独立字节读取 |
| §7.4 单序列 BD-rate | PCHIP，对数码率，分段解析积分，仅共同质量区间 | 固定官方工作簿、独立数学参考 |
| 产品范围与策略 | 原生逐行 BT.709 SDR、完整域声明、恒定帧率、每组至少四点、严格递增；元数据不足时拒绝参考模式 | 拒算与 JSON/界面检查 |

参考模式当前验证 YUV420 8-bit（yuv420p 或全范围别名 yuvj420p）及 10-bit little-endian（yuv420p10le），偶数尺寸，明确声明 BT.709 原色/传递/矩阵、tv/pc 范围及色度位置。直接比较编码值，不做范围扩展、采样转换或色调映射。跨位深归一化、HDR、其他采样/颜色域和未验证的 VFR 不进入这一配置，原来的相关功能仍使用原有行为。

原生试编码沿用已经核验的源片段、帧数与相对时间戳。额外解码只服务 BD-rate，禁止自动像素格式转换；逐帧整数 SSE 的上界须处于 JS 精确整数范围。内存中只保留有限帧缓冲和逐帧 SSE，不生成完整原始视频缓存。记录参考/候选像素流 SHA-256，核对测量前后文件身份；同一次计算所有点必须具有相同参考像素摘要、帧数、帧率及比较域，每条曲线固定编码器和设置。

H.264 / HEVC 由 FFmpeg copy 和 mp4toannexb 生成 Annex B 基本流，AV1 使用 low-overhead OBU；纳入码流头部，排除音频与容器。保存所采用表示的字节数和摘要，不能将其混称原视频包负载。HEVC decoded_picture_hash SEI 属校验信息，当前检测到即拒绝该点进入参考模式，不默默计入码率或删除所有 SEI。临时基本流统计后回收。CFR 检查使用有理帧率和源容器时间基容差，保存最大误差；不以平均时长掩盖 VFR。

## 算法、输入与解释

按质量递增排序，对 ln(rate) 作 PCHIP；Fritsch–Butland 加权调和内点导数及单边受限端点导数。分段多项式直接积分，不使用离散采样近似。积分范围是两曲线质量交集 [L,H]：

`BD-rate (%) = 100 × [exp(∫[L,H](ln R_test(Q) − ln R_anchor(Q)) dQ / (H−L)) − 1]`

自然对数和常用对数经相应指数变换得到相同定义。负值表示 Test 相对 Anchor 省码率，−20% 交换方向为 +25%。显示共同区间、两组覆盖比例和点数。探索 SSIM 的区间在 dB 域计算。参考模式提供独立 RD 采样图，使用与本次积分相同的基本码流码率和 PSNR-Y 帧均值；连线仅辅助审阅，不冒充 PCHIP 拟合曲线。原有试编码图表仍使用其原始口径。

有限质量、正有限码率、每组质量与码率严格递增、正宽度交集均须满足。重复质量、反向或相同码率、无限指标及缺失配置明确拒算；严格递增是软件的保守策略。不会自动删点、取包络、外推或补造分数。共同区间不足至少一条曲线跨度一半时给出软件诊断；0.5 是提示阈值，不是官方认证界限。零误差帧及其 999.99 dB 对均值的影响明确提示。还须结合曲线检查交叉、饱和与取样间距，微小差异不能直接视为稳定排名。

## 实验条件与声明边界

本功能在当前打开的一份试编码报告内选择 Anchor 和 Test，允许不同点数；不组合不同报告。原视频用于质量参考，自身一个码率不构成基准曲线。CRF 是获取 RD 点的取样参数，编码器/preset 可以是研究因素。

本配置对齐上述测量公式，结果明确记录 `conditions.fullCtc = false`。当前片段/CRF 试验不是完整 JVET CTC 执行器；不能仅凭四点或参考工具一致，就宣称复现某版规定的素材集、QP、帧数、AI/RA/低延迟配置与多序列汇总。本轮不新增完整序列基准调度，也不将 §7.6 多序列汇总标成已实现。

结果只代表已测片段和共同区间，不给出全片 CRF、确定体积节省或主观画质结论。不支持的参考配置保留明确 unavailable 原因，不阻断原有试编码指标；没有相应参考结果可导出。

## 导出、导入与复算

“导出当前 BD-rate 与完整复算依据”使用原 MediaScope 0.4 文件外壳，复制当前完整 trial 报告并增加可选 bdRateComparisons 数组。包括选择、模式、未舍入 RD 点、积分区间、覆盖、结果、文献/实现版本、测量配置及限制；逐帧分量 SSE、样本数、峰值/零值规则、像素/基本流摘要位于各行 bdRateMeasurement。完整报告保留源片段、编码设置、工具和命令。

导入先核对测量字段与报告来源/时间轴，按 SSE 重新求质量，按字节和帧率重新求码率，再用原始点重新积分并校验保存结果（均值 1e−10 dB、百分数 1e−9 个百分点、覆盖率 1e−12 的项目预算，兼容不同 JS 引擎的末位差异）；不信任保存的百分数字符串。此为一致性检查，摘要不能证明外来报告由真实测量产生或获得认证。导入保存了比较的报告会恢复该次选择。

原试编码导出仍保存完整输入测量，只有专用 BD-rate 导出额外保存当前选择；不增加后台自动长期保存。旧报告仍可读，原 pooled 含义不变，详见 [JSON 协议](json-format.md)。PDF 是呈现格式，不赋予权威性，本功能不新增 PDF 导出。

## 固定参考与精度判据

官方数据来自 [JVET-O0003-v1](https://www.itu.int/wftp3/av-arch/jvet-site/2019_07_O_Gothenburg/documents/JVET-O0003-v1.zip) 三份工作簿，宏参考另见 [JVET-T2010-v2](https://www.itu.int/wftp3/av-arch/jvet-site/2020_10_T_Virtual/documents/JVET-T2010-v2.zip)。锁定原档案/工作簿摘要，自动测试直接读取公式所引用的 RD 数据和原有缓存答案，不运行宏，也不宣称在 Excel 内重算通过。固定输入正文仅按 fixtures.lock.json 准备到 .build，测试目录仅维护读取器和断言。

对固定官方 RD 输入及已列明的数学对照输入，数值核验采用绝对误差 ≤1e−10 个百分点。外部依据为 [FAU-LMS/bjontegaard 固定提交](https://github.com/FAU-LMS/bjontegaard/blob/aef9b4d96c52873833cb76ebbe38eb928e0f5da7/README.md)公开声明的 PCHIP 与 Excel 至少小数点后十位精度一致；该实现的 [bd_rate 输出已乘以 100](https://github.com/FAU-LMS/bjontegaard/blob/aef9b4d96c52873833cb76ebbe38eb928e0f5da7/bjontegaard/functions.py#L130-L137)，单位是百分数。本项目将这一精度目标落实为 1e−10 个百分点的绝对差断言；这是有出处的项目判据，不是 FAU 发布的正式 atol 条款，也不是 ITU/ISO 颁布的容差。判据及固定来源统一在 testing-tools/helpers/bd-precision.mjs，断言和数值测量记录直接引用，不按产品实测最大误差加系数选线，不由产品输出刷新参考答案。

不能把成熟项目的某个测试位数当成行业统一标准。作为工程实例，[Netflix/vmaf 固定提交的部分 BD-rate 用例](https://github.com/Netflix/vmaf/blob/272c5967701017b90a0ebcff24205e59dbba6421/python/test/calculate_bd_rate_test.py)使用 assertAlmostEqual(..., places=8)，而该函数返回比例（−0.1 表示 −10%），按差值舍入规则约对应 5e−7 个百分点；同文件的两项 JCTVC 对照采用 places=4，约对应 0.005 个百分点。这些是特定实现及向量的回归判据；其新版实现还使用 100 点梯形积分，不能把它与本软件解析积分的结果差异全部归因于浮点舍入。

上述数值门槛与导入时的 1e−9 个百分点跨引擎复算预算分开；后者是现有 JSON 一致性检查的兼容预算，不能拿来替代固定官方向量的更严格验收。像素 SSE 和样本数、码流字节、摘要及帧数必须精确一致；已知像素及独立 BigInt 解码参考的 PSNR/均值误差 ≤1e−10 dB，不使用 BD-rate 容差代替上游测量检查。

浮点计算一致性、少量 RD 点的插值/取样误差和实验条件可比性须分别验证。[The Bjøntegaard Bible](https://arxiv.org/abs/2304.12852v2)讨论加密取样、相对曲线差异及结果可靠性；其取样误差不是软件允许的浮点误差。对于新的数据域、极窄共同区间或病态曲线，不能凭有限固定向量通过就保证同样的误差上界；应补充高精度/独立实现对照和敏感性检查，不放宽验收线掩盖异常。

补充数学用例包括恒等、比例/反向、非均匀/不同点数、局部重叠、端点限制、非法输入；独立 SciPy 1.17.1 参考包括 FAU-LMS 示例和 ITU 表 1。印刷表格已舍入数据复算约 −37.47148439%，不是 ITU 原文发布的最终数值。BD 原始定义出自 G. Bjøntegaard 的 VCEG-M33（2001），历史全局 cubic 与现代 PCHIP 须区分。

真实浏览器覆盖参考/探索口径、拒算、方向互换、队列报告归属和 JSON 往返。覆盖映射与正式记录要求见 [测试规范](testing.md)。
