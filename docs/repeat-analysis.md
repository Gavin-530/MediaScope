# 重复画面与时间轴测量规则

本功能使用FFmpeg软件解码、原生样本直接比较、rawvideo/framehash SHA-256和FFprobe原始时间证据；持续低变化候选使用官方freezedetect。当前方法配置版本2。它测量文件内的解码画面，不鉴定录制故障、编码前取帧来源或真实采集帧率。已有版本1报告继续按“SHA-256指纹相同”解读，不升级为已逐值确认。

## 样本与精确判据

同一所选轨道按解码显示顺序逐帧分析，不旋转、缩放、裁剪、改变帧率、降位深或色调映射。版本2精确重复的最终判据是相邻帧紧凑原生字节直接相等（Node Buffer.equals），且所有非有效填充位已核定为零；在固定布局下等价于全部有效样本逐值相等，不依赖哈希无碰撞假设。第一帧没有前帧，N张帧有N−1次比较，单帧比例不可用。连续k次相等比较对应k+1张帧，额外重复记录为k，不等于全片唯一画面计数。

rawvideo编码器产生无行对齐填充的紧凑帧。允许的整数布局由明确格式描述确定，完整保留Y/U/V、R/G/B及Alpha。对不足16-bit的字存储及P010/P012逐字节检查所有非有效位为零，随后才允许存储字节指纹代表有效样本指纹；非零填充拒绝本次测量，不把填充差异计作画面差异。不接受RGB0等未验证X填充、浮点或调色板，不隐式改成支持格式。

同一次FFmpeg解码分别输出官方framehash及原生rawvideo；程序流式核对每帧字节数、填充位和独立计算的原生字节SHA-256，并检查两路摘要与帧序完全对应。帧属性扫描另外核对每帧尺寸/格式不变。任何截断、进程错误、数量或摘要不一致使本次重复测量失败，不从部分输出生成完整成功。

原生指纹、低变化筛查及按帧复核显式使用 `-reinit_filter 0`。仅禁用自动格式转换不足以阻止 FFmpeg 在帧间颜色范围或矩阵标签改变时重建滤镜图并将样本归一化到首次输出属性；重建还可能清空低变化历史及 `select` 帧序。实际尺寸或像素格式改变仍在扫描时拒绝，不利用此设置容忍布局改变。颜色解释标签逐帧单独记录，不参与样本相等；涉及这类标签变化、由修复前路径产生的报告需要重新分析，不能把既有摘要补写成已保留原样本的证据。

精确判据的数学含义限于样本表示。色彩标签不证明实际显示色彩正确，同样码值也不证明不同解释下视觉相同。持续静止和精确相等的统计分开。

## 非零差异测量与分类边界

版本2使用明确命名的 `native-integer-difference-v1`，这是本项目可复算的数学测量，不声称获得ITU或其他机构的重复帧分类认证。逐分量计算 `SAD = Σ|a−b|`、非零差样本数、最大绝对码值差；16×16不重叠块在各分量自己的采样网格上计算，完整计入右/下残块，选择 `blockSAD/blockSamples` 最高的块，同值时取行优先的第一块。保存整数 `[sad,changed,maxAbs,blockSad,blockSamples,blockX,blockY]` 及分量布局；不把色度网格坐标当作亮度坐标。Alpha参与全部测量。

归一化分量均差为 `SAD/(分量样本数×(2^有效位深−1))`；全样本显示均差使用全部分量SAD之和与全部样本数，最大块显示值为各分量最高块均差除以同一peak。使用完整可表示码值范围，不改用limited-range端点；这属于码值域差异，不是HDR亮度或人眼感知距离。在128MiB帧边界内整数和及块均值交叉乘积不超过JavaScript安全整数范围。相等帧差异字段为null（所有差异严格为零），第一帧相等标志及差异均为null。

幅度分档仅为“逐值相等 / 最大差1码值 / 最大差2码值 / 更大”，互斥且覆盖全部相邻比较；1或2不是权威重复阈值，也不是可忽略误差。非零变化一律不记为精确重复。编码误差、光标、字幕和真实缓慢变化可能产生相同幅度，不能单凭这些测量确定编码前是否复用同一画面。`sourceClassification.status=not-qualified`、`defaultEnabled=false`；尚无通过来源隔离保留集验收的来源分类器，不报告虚构的precision/recall。

独立标量参考逐样本、逐块复算整数结果，相等真值另由变化样本数严格为零判定，不复用产品的Buffer.equals结果作为答案。运行时像素格式清单与产品描述器的交集须逐项对应验证矩阵；文件能解码、像素布局能测量、某个官方滤镜原生支持，是三个不同条件。FFmpeg本身不能解码的文件不能通过自写差异算法补成可分析输入。

官方`identity`/MSAD原生支持的交集逐布局执行相等比例及逐分量均差对照，禁止隐式格式转换；当前参考配置固定 `-cpuflags 0 -filter_complex_threads 1`。官方滤镜不原生接受的布局，在独立整数真值外另用测试专用的可逆表示适配作交叉对照：只重排分量、解交织、换字节序或向更高位深精确嵌入，逐分量逐样本回读核对。嵌入`y=x×2^s`时，SAD、最大差及块SAD须精确乘`2^s`，变化计数、块样本数及坐标保持一致；上游均差按目标位深peak归一化，再按该明确关系解释，不能混用原/目标分母。不得降位深、缩放、重采样色度或色调映射。适配对照是本项目的等价性验证，不是官方原生支持或认证，也不是产品分析时的预处理。P010等raw验证仍不扩大为通用载体兼容。

默认SIMD/线程配置在本机的小尺寸色度样例曾不符整数真值，原始输出继续保留，未授予该配置正确答案资格。上游metadata经过float参数并以六位小数输出；对`[0,1]`范围的对照，舍入界按`0.5×10^-6 + 2^-25 + Number.EPSILON`推导，不能用于放宽整数证据或严格相等判据。日志舍入为0/1不能证明样本相等。这些检查只验证明确的布局、数据及工具配置，不等于遍历所有媒体、编码/容器组合、工具版本、场景或完整FATE套件；MSAD/identity仅用于验证，不是新增生产运行依赖。

## 连续样本不变与实际静态内容

版本2另提供 `sample-constant-original-pts-v1`：精确连续段具有至少2秒的已观察原PTS跨度，才列为连续样本不变区间。段内PTS必须存在且严格递增；若下一不同帧的原PTS可用，可证实该保持段的闭合边界。文件尾只用实际末帧PTS判断最低已观察跨度，末帧duration即使很长也不能单独把不足2秒的观察补成合格。区间仍保留精确段原有边界及其依据，并另存observedEndPts/observedTicks；缺PTS、非递增或缺时间基分别保留partial/unavailable与未核定段数。

这测得的是解码样本持续不变，不识别现实场景或拍摄意图。自然静态内容也可满足；实际静态但有压缩噪声的内容可能只满足低变化候选。精确、持续样本不变、阈值低变化可重叠；不相加，不称作故障率。

## 原始时间证据

分别保存FFprobe逐帧pts、best_effort_timestamp、整数duration及原time_base。本文的“原始PTS”指FFprobe报告的源帧pts，包含工具的解复用/解码解释，不声称直接解析了容器裸字节。framehash输出的时间基、PTS和duration另存，它们可能由编码/复用过程生成，不能冒充源帧PTS。源帧PTS缺失仍可比较有序样本，时间结论则部分或不可用，程序不回退DTS、不用平均fps补造。

帧间隔在整数tick域统计。候选帧率仅取有效的轨道r_frame_rate/avg_frame_rate，不根据画面重复数量寻找一个想要的帧率。对原PTS完整、严格递增且时间基小于候选帧周期的数据，核对每帧`abs((pts_i−pts_0)*time_base−i/f) <= time_base`，采用BigInt有理数比较。一个源刻度覆盖两次独立量化相减的误差。报告称“与候选网格相容”，不认证CFR采集；29.97fps的33/34ms量化交替不直接判为VFR。

连续段由首帧原PTS开始，到下一张不同帧的原PTS结束；若延伸到文件尾，只使用FFprobe报告的有效末帧duration，并明确标记last-ffprobe-duration。该字段可能经过工具推断，不认证容器中存在显式末帧时长。段内缺PTS/非递增、末边界未知时保留开放结束，不用平均fps填补。VFR一张长持续帧不会增加重复记录次数。

## 持续静止候选

显式选择后调用固定`freezedetect=noise=0.001:duration=2`。它比较画面变化是否低于阈值并满足时长，属于候选筛查；不等于精确相等或故障。只在原始时间证据完整、递增且已验证布局支持时启用，不静默转换高位深、Alpha或像素布局。

保留上游metadata的start/duration/end字符串、实际报告该事件的帧号和滤镜PTS。上游时间字符串受日志格式精度限制；报告事件帧是“检测到事件时的帧”，不能当作冻结起点帧。EOF只有start时保留开放事件，不补造end。方法不支持或出错单独说明，不把空事件列表冒充已完成检查。

## 报告与复核

结果页默认展示三组聚合统计，宽屏均分一行，主数字使用24px；相邻比较次数、重复比例及已证实持续不变段数与主数字同行，空间不足时自然换行。分析规模合并帧数与相邻比较次数，精确重复合并次数与比例，连续重复段合并总段数与其中由原 PTS 证实至少2秒的持续不变段数。零值明确显示，部分可用或无法核定时保留状态及原因，不把未知当作零。窄屏改为单列，保留主数字字号，不靠缩小重要数据压缩版面。

完整且严格递增的原始时间戳状态只在“检测明细与导出”的时间戳部分显示，模块标题只保留名称；缺失时间基、时间戳异常、单帧不可比较、持续时间未核定及旧版指纹方法限制在板块展开时直接显示，随整个板块一起收起。默认视图不重复解释已经显示的零计数。原生格式、位深、比较判据、N−1次比较、通用判读说明移入已有的“方法与判读依据”；“正常静止也可能产生重复，不能据此认定录制故障”同时保留在精确重复标签的提示中。图表标题旁只显示每柱最多覆盖多少次相邻比较；点击定位及聚合不改变原始计数的完整说明保留在方法明细和该标签的提示中。标题旁的说明不沿用段落的上下边距。

四档相邻差异次数、重复段、时间戳/间隔、逐帧证据及各自CSV保留在默认收起的“检测明细与导出”。相邻差异分档不解释为异常等级或视觉差异程度。首次展开明细时才填充各表的一页数据。原帧复核单独按需展开，点击图表或明细中的定位会自动打开复核入口。持续静止筛查放在分析设置的“高级选项”，未选择时不显示对应结果栏；实际选择后，候选直接作为背景阴影融入现有精确重复分布图，不再建立独立时间带。曲线仍只表示精确重复次数，低变化候选不会增加计数。悬停同一图表可查看候选序号、原始起止时间和上游持续时长；候选区间内点击定位其检测事件帧，其他位置按相邻比较定位。完整表格、筛查判据及CSV在图表下方的“静止候选 · 明细与 CSV”，原始事件再按需展开。没有候选或筛查失败时明确显示相应状态。仅调整展示和说明位置，不删减测量字段、CSV/JSON证据或改变统计，旧方法报告不补造新方法统计。

明细展示重复段数、可用间隔种数、静止候选段数或具体不可用状态，不用“已完成”代替检测结论。未发现重复、未检出静止候选、单帧无法比较、缺少时间戳或候选帧率均须说明，空表不作为结论。原始 PTS 完整且严格递增时，分布图横轴使用原始时间，每组相邻比较覆盖其前帧 PTS 至末帧 PTS，最小缩放跨度保留到实际帧间隔；其他情况保留显示帧序号，不重建缺失时间。计数分组仍按相邻比较次数，时间坐标不把计数换算成频率。候选阴影使用检测器报告的时间边界，与图表共用坐标和缩放；开放区间用斜纹延伸至末帧原始 PTS，省略确定结束边线，读数仍明确显示开放，缺少的时长标为未知，不推算结束或持续时长。悬停读数和表格保留检测器的原始秒数字符串；定位检测事件帧不冒称定位区间起点。区间、事件及逐帧证据按每页50项按需展示，CSV导出全部记录；不足一页时隐藏翻页按钮，空结果仍可导出表头。实现配置、命令与文件身份摘要的详细说明保留在本文及完整报告，页面只在相关结果和复核入口保留必要的判读提示。

报告保存配置、实际输入表示、文件身份、命令、帧摘要、两类时间证据、计数与区间、静止事件及方法状态。JSON统一导出0.5，读取0.4和0.5时均重新核对派生统计；旧报告缺该字段显示未计算。预览按帧序重新解码并核对指纹及文件身份，显示用转换不参与分析。HDR/高位深预览和显示差分不能证明原生样本没有微小差异。

重复次数图的自动纵轴从零开始，刻度间隔为整数；上限可向上扩展到覆盖最大计数的刻度。自动模式下全零或仅有0/1时显示0和1。手动范围原样采用用户上下限，可以不从零开始；只在范围内绘制整数刻度，不把用户边界扩展到整刻度。范围锁定、超界提示及保存边界遵循[图表范围规则](chart-controls.md)，不改变分组、计数或导出数据。

文件元数据身份摘要取设备、文件标识、长度及纳秒修改/状态时间。版本2另在分析前后完整读取源文件SHA-256；预览传入该字段时也在前后核对。报告记录实际FFmpeg、FFprobe与Node可执行文件路径和SHA-256；工具摘要按文件元数据身份缓存，不能当作防恶意替换的外部证明。元数据检查、内容摘要、报告结构一致性均不是作者认证或外部鉴定；导入校验不能证明一份自洽报告没有被人重写，原文件复核仍有必要。CSV使用UTF-8 BOM、CRLF、双引号转义和固定列数，每行携带方法版本、时间基和来源表示；版本2增加内容摘要、差异配置及来源分类状态，逐帧CSV包含直接相等标志与逐分量整数差异。不写非标准注释行。CSV和JSON均遵循256MB输出边界，超限拒绝，不截断为完整成功。格式及兼容边界见[JSON 文件协议](json-format.md)。

## 格式与资源资格

精确分析已知字节文件矩阵覆盖整数YUV420/422/444的8/9/10/12/14/16-bit、实际存在的YUVA布局、GBRP/GBRAP、灰度、RGB/BGR与四通道排列、NV12/NV21；多字节包括大/小端。使用奇数尺寸并逐分量改变左上、末边缘和最低位，独立核对完整字节摘要与相等掩码。测试范围与实际工具身份保存在正式测量证据中，不推断任意编码器和容器均可保存这些表示。

P010/P012/P016另以显式raw输入核对官方原生framehash、有效位与填充位，覆盖大/小端；这不认证自动探测文件链路。FFmpeg 8.1.3中已发现P010 rawvideo写入NUT后自动解码为rgb555le的案例，产品明确不支持该表示。首版不提供raw文件的像素格式/尺寸/帧率输入界面，不把raw链路测试当作所有P010文件兼容证明。遇到自动探测/解码不正确的载体，须使用能正确声明并保留样本的外部无损封装，或等待独立验证的输入扩展。

持续静止资格与精确判据分开。原生白名单的51种表示均以控制样本检查静止起点、闭合区间、持续高变化和开放EOF，并逐项对照上游事件，包括YUV420/422/444、灰度和GBRP的8/9/10/12/14/16-bit小端、GBRAP8/10/12/16、YUVA8/10/16、RGB/BGR及四通道排列、NV12/NV21。这些是项目控制输入的上游实现对照，不冒称51套官方FATE原向量；官方冻结检测FATE原用例另按其原始图形与参考答案验证。非白名单返回unsupported，实际滤镜失败返回failed，不伪装为空候选。关闭该可选方法不影响精确分析。

每帧紧凑原生字节上限128MiB，解码帧数上限2,000,000；另检查可用内存和Node堆预算。版本2使用两个固定大小原生帧缓冲及临时块和数组，媒体字节流式处理，报告元数据随帧数增长，不声称全程恒定内存。完整扫描帧属性后再解码比较、核对指纹；低变化另作可选读取，版本2新增源文件前后内容摘要读取。普通启动不增加能力扫描，安装和显式检查验证新增能力；可选能力缺失不阻止其他已有功能。汇总、时间网格和最终验证按有界批次让出事件循环，批次间检查取消；同步报告校验仍使用相同计算步骤，不改变报告结构或旧方法含义。

`node testing-tools/repeat-resource.mjs boundary`单独验证重复分析自身的两百万实际帧及超限拒绝、128MiB原生帧末样本差异、1080p/4K/8K扫描与比较阶段取消。`long`额外评估30分钟1080p120、10分钟4K120静态无损控制长片；不传参数则执行两部分。长片时长来自项目工程计划，不是FFmpeg或NIST规定，不是判重数学正确性的验收前提；仅在专门评估长时间稳定性时执行，不因局部修改自动扩展为必做任务。父进程独立计量取消请求到工作进程及其管道结束的时间，使用实际进程工作集/峰值工作集与Node内存观察，不用分析进程自身的阻塞定时器证明响应；2秒响应观察目标与5秒取消目标属于项目工程条件。内存采样可能漏掉短峰，静态控制长片不构成运动素材或其他机器的吞吐保证。已有版本1结果不能当成版本2资格；其他模块的帧数测试也不能替代本项。版本2通用回归另含实际1080p静态/运动、4K运动短片、两个8K灰度16-bit最低位差异帧及取消，不从短片推算长片性能。

## 验证依据与范围

独立已知字节生成器不导入产品格式读取或统计函数，逐样本构造预期相等掩码。正式验证包括边缘、色度、Alpha、最低位、各支持布局、缺PTS、NTSC量化、VFR保持、损坏与取消，另外对照真实FFmpeg原始输出。运行可用不等于所有格式已验证；产品支持矩阵以测试范围和具体方法为准。

维护中的`repeat-qualification.test.mjs`纳入通用回归及正式测量采集。固定上游输入从`fixtures.lock.json`的来源下载并核对长度和SHA-256：NIST字节型SHA-256短消息、长消息、Monte Carlo及中间答案；FFmpeg固定提交的freezedetect FATE定义、完整参考输出及相关源码/许可。原始FATE文本只规范换行，不调整数值；保存同一控制视频经过产品链路后的事件、帧序和时间基核对。NIST仅验证所用哈希实现，不定义重复帧、静态场景或来源分类。

所有声明整数布局的每个分量均遍历全部可表示码值，逐样本回读，并以补码值对照直接比较、整数差异和可逆表示适配的比例关系；同时检查非有效位为零及奇数尺寸边界。这是有限整数域的映射与算术验收，不声称遍历所有视频帧组合。官方原生滤镜对照、项目表示适配对照和项目数学真值分别记录；CSV另在实际UTF-8 256,000,000字节上限及超出1字节处验证完整接受/明确拒绝，包含BOM、引号、换行和多字节字符。

上游依据：[NIST FIPS180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final)规定SHA-256而非整套视频判定；[framehash](https://ffmpeg.org/ffmpeg-formats.html#framehash)、[FFprobe](https://ffmpeg.org/ffprobe.html)、[MSAD](https://ffmpeg.org/ffmpeg-filters.html#msad)、[freezedetect](https://ffmpeg.org/ffmpeg-filters.html#freezedetect)规定各工具行为。实际工具身份、版本与命令及数值对照保存在报告和测试证据中。兼容其他稳定版本须通过同一测量检查，不用在线文档代替实际程序能力。[NTIA TM-09-456](https://its.ntia.gov/publications/download/TR-09-456.pdf)讨论正常静态/重复源与估计丢帧的歧义，原文阈值为初步推荐，不能作为通用准确率认证；[VIVTC](https://github.com/vapoursynth/vivtc)仍是候选研究参考，本轮未引入为生产运行时，也不把其周期删帧决策当作重复真值。
