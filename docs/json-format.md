# JSON 文件协议 0.5

本协议定义文件组织、无损表格编码、测量配置与扩展边界。文件版本、软件版本、测量方法版本和摘要算法相互独立；新增方法、摘要配置或可选证据可在本协议内扩展。协议修订不等于发布软件安装包，软件发布另遵循[发布规范](releasing.md)。

JSON 数据类型依据 [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259)，Base64 表示依据 [RFC 4648 第3.2、3.5及4节](https://www.rfc-editor.org/rfc/rfc4648)；SHA-2、SHA-3 算法名称及输出长度分别依据 [NIST FIPS 180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final)、[FIPS 202](https://csrc.nist.gov/pubs/fips/202/final)。字段组织、能力标识和结构预算属于本项目的协议约定，不是这些标准对重复帧检测的认证。

报告接口和用户主动导出使用相同的普通 JSON 协议。所有用户导出包括单份结果、多份结果、待运行计划以及两者混合，不按用途派生另一套格式。结果仅在本次服务的内存中保留；导入的 JSON 在当前页面解码查看，不自动保存副本。

## 版本与兼容边界

新导出及报告、计划接口统一写出 `0.5`，读取接受字符串版本 `0.4` 和 `0.5`，并执行相应结构和证据一致性校验。已有0.4及早期0.5草案的重复帧方法1/2记录仍可读取，保留原始字段和测量含义。`0.3`及更早封装、未知外层版本和数字版本明确拒绝，不猜测或自动降级。

0.5可保存独立分析目标、重复帧、原始时间证据及可选低变化候选。早期读取器可能不识别这些目标和方法，不能因表格编码相同就宣称双向兼容；不应只改文件版本号绕过校验。缺少重复帧字段的旧报告保留未计算状态，不补造分析。本版提供保存报告的读取、校验和摘要展示；文件协议不代表已经启用重复帧计算或原帧复核后端。

文件外壳和明细表编码规则继续沿用既有形式，数值不舍入，容量上限不变。重复帧测量已由方法版本1扩展到版本2，其判据和证据差异由 `repeatAnalysis.configurationVersion` 区分，不能将外层版本仍为 `0.5` 理解成测量定义未变。其他指标配置及第三方日志版本按各自方法保留。导入不会改写源文件；重新导出保留原报告的时间、工具、配置、原始证据和测量值，不将旧方法补写成新方法。

## 文件头和内容

顶层字段为 `format: "MediaScope"`、`formatVersion: "0.5"`、`createdAt`、`producer`、`results`、`plans`和`timing`，可选`requires`声明必需能力。版本号使用字符串，文件格式版本只在顶层出现一次。单份报告不含`schema`或另一个`formatVersion`，测量及配置自己的版本另行保留。软件设置、任务状态、失败记录、测试证据和第三方原始日志不属于本协议。

`producer.applicationVersion` 是本次写出文件的实际应用版本。`createdAt` 是文件生成时间，默认使用 UTC 秒级 RFC 3339。来源已有小数秒原样保留；媒体时间戳、时长和计算耗时不按秒截断。日期规则见[数据与归档](data-and-archives.md#日期与时间)。

`results` 和 `plans` 都是最多 10,000 项的数组，单个数组内 `entryId` 为非空且不重复的字符串。每项结果包含 `report`，每项计划包含 `input`。计划参数由服务端逐项验证后才允许排队；查看结果不会自动创建计划。没有内容的用户导出和导入拒绝；空计划列表接口仍能返回同一协议的空列表。

结果保留原有生成时间、`producer.applicationVersion`、素材与轨道信息、工具版本、命令及耗时、指标配置、逐帧与逐包数据、汇总、原始证据、警告、不可用/失败/资源受限状态。重新导出只更新外层生成信息，不覆盖每份结果的来源。`type` 为 `inspect`、`analyze`、`compare` 或 `trial`；前两者归入文件分析功能。

按目标运行的 `analyze` 报告增加 `analysisTargets: {frames, bitrate, complexity}`，三项均为布尔值；选择重复帧时另加 `repeat: true`，未选时省略，全部目标至少一项为真。`frames` 或 `complexity` 开启时保存核验显示帧及汇总；`frames` 开启时保存编码结构。`frames` 或 `bitrate` 开启时保存轨道包统计及所选轨道引用；仅选 SI/TI 或重复帧时不保存这些包字段。关闭 `bitrate` 时各轨道 `bins` 为空且不保存 `bitrateCurve`；开启时遵循原窗口协议。未选项目不以空图或失败结果代替。无 `analysisTargets` 的旧报告继续要求原完整分析字段。

计划按原样保存 `input`，排队前再由当前后端逐项验证。已实现重复帧计算的后端使用 `repeatAnalysis` 与 `freezeDetection` 开关，缺省均关闭，低变化检测必须同时选择重复帧；当前主线只读保存结果，拒绝执行这些计算参数，不静默忽略。能保存计划不代表当前后端能够执行其中所有参数。

`repeatAnalysis`方法2保存原生格式、文件元数据身份与完整内容SHA-256、工具身份、逐帧直接比较与整数差异、持续样本不变区间、来源分类未获资格状态，以及源帧/摘要输出各自时间、精确段、时间网格和可选低变化事件。逐帧摘要可以采用既有SHA-256表示或下述独立公共摘要配置。方法1继续按原SHA-256相同解释；未支持状态保存原因，未选择时无此字段。导入校验不能证明报告未经自洽改写，也不能离开原文件复算像素差异或摘要。

`timing` 为所含结果的计算耗时汇总，读取时核对一致性。各指标自己的配置版本、实施解释、模型和工具版本继续保留，不等于重复的文件版本。原始日志字符串逐字保留；原始 JSON 对象的属性顺序和排版不承诺与工具输出文本相同。

## 重复帧子协议与方法版本

外层 `formatVersion` 标识文件封装；`repeatAnalysis.configurationVersion` 标识重复帧测量及其证据要求。两者独立。当前读取器接受方法版本1和2，未知方法版本明确拒绝；旧读取器即使接受外层 `0.5`，也不保证理解方法2。已有0.4或早期0.5的方法1报告保留其原始方法含义，不转换或补造方法2证据。

| 内容 | 方法版本1 | 方法版本2的完整结果 |
| --- | --- | --- |
| 相邻精确判据 | 原生样本SHA-256相同 | 原生样本字节直接比较；声明的帧摘要另作核对证据 |
| 逐帧比较字段 | 不补造 | `equalPrevious`、`difference` |
| 文件与工具身份 | 原文件元数据身份 | 另保存 `source.contentSha256` 和必需工具的 `tools` 路径/摘要 |
| 非零差异 | 未计算 | `differenceConfiguration`、`differenceSummary`及逐分量整数证据 |
| 持续样本不变 | 未计算 | `constant`配置、状态及`segments`区间表 |
| 编码前画面来源分类 | 不据此推断 | `sourceClassification.status: "not-qualified"`且`defaultEnabled: false` |

方法2第一帧的 `equalPrevious` 和 `difference` 均为 `null`，表示没有前帧。后续相等帧为 `equalPrevious: true`、`difference: null`，此处表示所有分量差异严格为零；非相等帧为 `false`，`difference`按 `differenceConfiguration.components` 顺序保存分量数组。每个数组的顺序固定为 `sad, changed, maxAbs, blockSad, blockSamples, blockX, blockY`，分别为绝对差之和、变化样本数、最大绝对码值差、最高均差块的绝对差之和、该块样本数及分量网格起点。它们都是未经舍入的非负安全整数；布局、有效位深峰值、16×16块及完整边缘块规则由配置声明并校验。`differenceConfiguration.method` 当前为 `native-integer-difference-v1`，它不等于整个重复帧方法的版本号。

`exact`保存相邻比较的精确重复次数与连续段；`differenceSummary`将全部比较分成相等、最大差1码值、最大差2码值及更大四档，非零差异不计为精确重复。`constant`使用原始PTS确认至少2秒的样本不变区间，仍属于`exact`的重复段，不从总计中扣除；`freeze`保存可选上游低变化筛查，可能包含非零变化，不能并入精确重复计数。缺失的持续时长不能按平均帧率补造。这些记录不判定录制丢帧、真实静态场景或编码前是否重用同一画面。

导入按方法版本核对完整字段、整数边界及派生量；重新导出保留方法版本和原始测量。来源/工具摘要和内部一致性不能证明测量实现没有缺陷。已有实现缺陷影响的报告须在可靠实现中重新分析，不能通过修改JSON版本或补字段追认原结果。

方法2有两种互斥的摘要表示：既有`algorithm: "native-bytes-equal+FFmpeg/rawvideo/framehash/SHA256"`配合逐帧`sha256`，不补写公共摘要配置；通用表示使用`algorithm: "native-bytes-equal+frame-digest/v1"`、公共`fingerprint`配置及逐帧`digest`，不同时保存`sha256`。方法1只接受原SHA-256表示。两种方法2表示均以直接比较决定精确相等，不以摘要相同反推样本相等；相等帧必须有相同摘要，摘要相同的非相等帧仍按非相等记录。

## 公共帧摘要配置

`repeatAnalysis.fingerprint`每份重复帧结果保存一次，逐帧只保存摘要值，不重复配置：

| 字段 | 版本1的定义 |
| --- | --- |
| `version` | 数字1，标识本配置结构 |
| `algorithm` | 1–80个小写ASCII字母、数字及`._/-`组成的算法标识，首字符为字母或数字；同一标识的语义不得改变 |
| `bits` | 8–4096的整数，须是8的倍数；是本条摘要的完整输出长度，不是文件/原生帧字节数 |
| `encoding` | `hex`为小写十六进制；`base64`为RFC4648标准字母表及必要填充的规范表示；长度和未使用位必须一致 |
| `input` | 固定为`native-frame-bytes`；完整紧凑原生帧，字节布局由`sampleFormat`声明，不含时间或色彩标签，不缩放、降位深或重排为显示RGB |
| `parameters` | 必需的JSON对象，显式记录seed、variant等算法参数；无需参数时为`{}`。大整数参数用十进制字符串 |
| `extensions` | 可选的非关键元数据对象，遵循下节结构预算 |

已知SHA-224/256/384/512、SHA-512/224、SHA-512/256及SHA3-224/256/384/512分别用`sha224`、`sha256`、`sha384`、`sha512`、`sha512-224`、`sha512-256`及`sha3-224`等标识，长度必须与名称一致，参数对象为空；不能将截断、HMAC或改变初始状态的结果冒称同一算法。其他算法标识及参数可以作为声明数据保存，但不因此获得计算实现、抗碰撞性或原文件复核资格。当前导入只验证配置、表示与统计的一致性，不运行文件指定的算法或插件。

`source.contentSha256`、文件元数据身份和`tools[].sha256`仍按既有SHA-256语义保存；通用帧摘要不偷偷替换这些不同用途的摘要。既有方法2保持原三项工具身份；通用表示允许3–32项唯一工具角色，仍必须包含`ffmpeg`、`ffprobe`和`node`，其他角色须用有界小写标识及实际路径/SHA-256记录。CPU/GPU、库或驱动变更本身不改变摘要定义；分块摘要拼接、输入域改变等不属于同算法的等价实现。

通用摘要配置不改变原生直接比较、差异单位、时间证据来源及其验证规则。需要改变这些测量语义时，应另行定义方法或配置版本，不能仅修改算法名称。同一外层0.5允许更新读取器支持新方法，旧读取器不理解必要方法时必须明确失败。

## 可选扩展与必需能力

单份报告可带`report.extensions`及`report.requires`；重复帧结果和公共摘要配置也各有可选`extensions`。扩展放在报告内，导入查看后重新导出或组合多份结果时随各自报告保留，避免不同来源的文件级元数据相互覆盖；不接受顶层`extensions`。扩展不得覆盖、重解释或代替必需测量字段，未知可选内容仅作为数据保存，不执行或据此授予验证资格。

元数据对象只接受有限数值、字符串、布尔值、null、稠密数组和普通JSON对象；最大深度16、最多10,000个访问节点。拒绝循环、BigInt、undefined、NaN/Infinity、访问器、不能序列化的属性及`__proto__`等保留键。此预算不替代256MB文件和各明细表行数限制。

`requires`为最多64项、不重复的能力标识数组。当前标识为`table/1`、`repeat/1`、`repeat/2`和`frame-digest/1`，分别表示既有表格编码、两种重复帧方法及公共摘要配置。读取器先检查文件级列表，再检查报告及具体方法；未知必需能力明确拒绝，不按可选字段忽略。写出时合并报告声明与所需方法生成顶层列表，未使用时省略；仅新增数据能力而未改变文件外壳时可增加标识，不必改变外层版本。重新选择结果导出会重建文件级能力列表，各报告自己的声明保持原状。

新方法/摘要配置、可选字段和新能力标识均须保留旧语义与旧记录读取路径。改变文件外壳、表格编码或既有字段意义等不兼容变化时仍须重新评估外层版本，不能承诺任意变化永久兼容，也不因上游软件版本号变化自动改号。

## 明细表

只对明确列出的路径采用表格编码，不递归重写原始证据：

| 路径 | 编号规则/上限 |
| --- | --- |
| `report.frames` | 每行一个原显示帧；最多 2,000,000 行 |
| `report.repeatAnalysis.frames` | 第 i 行的 `frame` 固定为 i；最多 2,000,000 行 |
| `report.repeatAnalysis.exact.runs` | 连续相邻精确重复段；最多 2,000,000 行 |
| `report.repeatAnalysis.constant.segments` | 版本2中原PTS证实至少2秒的连续样本不变区间；最多 2,000,000 行 |
| `report.repeatAnalysis.timeline.intervals` | 整数 tick 间隔及次数；最多 2,000,000 行 |
| `report.content.points` | 第 i 行的 `frame` 固定为 i，省略重复编号 |
| `report.content.scenes` | 第 i 行的 `index` 固定为 i；最多 2048 行 |
| `report.coding.packets` | 第 i 行的 `index` 固定为 i；最多 500,000 行 |
| `report.coding.events` | 第 i 行的 `id` 固定为 i；最多 750,000 行 |
| `report.coding.gops` | 第 i 行的 `index` 固定为 i |
| `report.tracks[].bins` | 原秒级码率记录；最多 1,000,001 行 |
| `report.tracks[].bitrateCurve.bins` | 原精确区间码率记录；最多 1,000,000 行 |

这些是原有分析/校验预算，不额外提高计算上限。音频逐包记录原本已经是固定四列数组，继续保存原结构，最多 500,000 行。比较指标的数值数组、原始日志和试编码各参数组合保留现有内容。

每张表含 `count`、`columns`、`rows`，可选 `constants` 和 `sparse`：

- `count` 等于 `rows.length`，每行长度等于 `columns.length`，列名唯一。
- 每行都存在且值完全相同的字段放在 `constants` 中，只存一次；不是从第一帧或轨道声明推断全片恒定。
- 每行存在且变化的字段列入 `columns`，对应值按列顺序存入 `rows`。
- 只在部分行存在的字段放在 `sparse` 中：字段名对应按行号严格递增的 `[rowIndex, value]` 数组。没有该行表示字段缺失，值为 `null` 表示明确空值。
- 三组字段互不重叠；不能与该路径的隐含编号冲突；拒绝重复、负数或越界索引，以及原型污染键。缺列、缺行、非法数量和截断 JSON 明确失败。

解码后还核对必需字段及语义：显示帧的 PTS、时间、时长、体积、帧型和布尔标记不能整列缺失；汇总帧数与明细一致；视频包保留原有基础头记录，AV1 事件保留原始 `fields`；帧、包与事件之间的引用不能越界。校验不能证明文件从未被人为改写，但不会把已识别的缺失或矛盾内容当作完整结果。

表格不抽样、不舍入、不丢弃记录，不转换为 Float32。大整数 PTS、区间分子、精确字节计数等原有十进制字符串继续原样保存。扫描和 SI/TI 的时间戳分别保存，不根据平均帧率重建或因容差内相近而合并。

## 去重与来源

完整分析的所选视频轨道由 `report.stream` 唯一定位到 `report.tracks`。文件不再保存重复 `report.packets`；解码时引用对应轨道还原原界面模型。编码前两者若不一致则拒绝写出，不静默舍弃其中一份。

场景声明、码率曲线、音频包分布在旧内存模型中的结构版本固定由本协议定义，文件中省略这些 `version: 1`，解码时恢复。SI/TI `configurationVersion`、模型和原始证据中的版本不移除。完整像素格式目录和各轨道记录保留，不把不同音轨当作重复对象。

## 文件名

仅四个模板，变量只有源文件基名和 UTC 导出时间：

| 功能/内容 | 模板 |
| --- | --- |
| 文件分析，读取信息或完整分析 | `MediaScope-analyze-<file>-<UTC>.json` |
| 质量比较 | `MediaScope-compare-<UTC>.json` |
| 片段实验 | `MediaScope-trial-<file>-<UTC>.json` |
| 实际导出两项及以上 | `MediaScope-queue-<UTC>.json` |

单项计划和结果使用同一所属功能模板；一次试编码的多个 CRF 不算多项。时间使用 `YYYYMMDDTHHmmssZ`，不增加版本、数量、计划标签、随机码或软件自定义避重编号。源名只取最后一个路径分量，保留原语言和扩展名，清理 Windows 非法字符和尾部点/空格，并限制长度；无可用源名时使用 `media`。浏览器可能自行处理同名下载，这不是本软件模板的一部分。导入不依赖文件名。

## 保存、限制和旧文件

文件紧凑序列化；用户主动导出时通过下载保存，不自动写入运行目录。导入/导出上限为 256,000,000 字节。没有引入 JSONL、压缩包或新的自动格式切换。

解码后完整对象仍驻留内存，因此磁盘体积减少不代表内存按相同比例减少。整份 JSON 字符串、解析及绘图仍有资源边界；不承诺所有设备均能处理最大帧数、分辨率或最大文件组合。

## BD-rate 可选测量与比较

trial 的 rows 可增加 bdRateMeasurement（version: 1）。status 为 ok 时，保存固定 profile、比较域、帧数、位深峰值、零 MSE 规则、Y/U/V 样本数/逐帧整数 SSE/PSNR 均值、参考与候选像素 SHA-256，以及基本码流格式/字节/摘要/CFR 帧率/时长/码率和时间核查。status 为 unavailable 时保存 version 和非空 reason。旧报告缺少该字段仍可导入，不能据此生成参考模式结果。

专用 BD-rate 导出在完整 trial 报告增加 bdRateComparisons，最多64项；每项保存 anchor、test、metric、profile（reference 或 exploratory）和 result。导入核对测量与源格式/时间轴，重新求均值与码率、重新积分，并比较保存结果及依据配置；改动结果或不一致配置明确拒绝。缺少这两个可选字段的0.4和0.5文件含义不变；这是带独立测量版本的可选证据扩展，新导出外层统一使用0.5。原 pooled PSNR 与新 PSNR-Y 分开保留，不迁移或重解释旧值。协议校验只证明记录内部一致，不证明外来报告的真实来源。详细公式、参考版本和边界见 [BD-rate 测量规则](bd-rate.md)。
