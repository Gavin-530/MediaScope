# MediaScope 发布规范

## 版本与命名

| 对象 | 格式 |
| --- | --- |
| 版本 | 与 `package.json` 一致；预发布使用 `-alpha`、`-beta`、`-rc`，可附 `.数字` |
| Git Tag | `v<版本>`，指向本次测试和打包的同一提交 |
| Release 标题 | `MediaScope <版本>` |
| Windows x64 ZIP | `MediaScope-<版本>-win-x64.zip`，包内版本与文件名不加 `v` |

修复递增补丁号，兼容功能新增递增次版本号；不兼容变化在 `0.x` 阶段递增次版本号，`1.0.0` 起递增主版本号。预发布在 GitHub 标记为预发布。同版本不能替换附件或覆盖已有本地包；历史包保留原名。

## 发布检查

1. 按[贡献与提交规范](contributing.md)完成并提交计划发布的变化，运行 `npm run check:commits` 并审查说明与实际差异；核对版本、目标提交及 Tag，不能因版本号相同就认定源码相同。版本号在发布计划中确定，不仅凭提交类型自动改号；发布准备标题的版本必须与对应提交一致。
2. 在干净工作区运行完整发布回归：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/record-test.ps1 -Kind App -Release
   ```

   任何失败、跳过、未完整覆盖或归档阻塞都不得发布。详细门槛见[测试规范](testing.md)。
3. 运行 `scripts/package.ps1 -Version <版本>`，生成一个 Windows x64 联网部署 ZIP；不覆盖已有包或暂存目录。
4. 对确切附件分别完成离线与真实首次联网部署：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/record-test.ps1 -Kind Package -Archive <zip> -RequireClean
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/record-test.ps1 -Kind OnlineDeployment -Archive <zip> -RequireClean
   ```

   核对 SHA-256、字节数与结构化结果；另在锁定私有环境下运行应用回归。离线运输夹具不能证明联网下载通过。
5. 完成人工验收及兼容性检查，保留对应记录和未验证的 Windows/运行时范围。
6. 使用 [Release 模板](../.github/RELEASE_TEMPLATE.md) 创建草稿，审查正文；检查准确提交、最新目标分支、冲突、远端必需检查与审批。接入 [GitHub 自动测试](github-actions.md) 后，核对针对确切发布 SHA 的完整回归；PR 合并提交的通过不能直接证明另一个 Tag 提交通过。远端证据上传未启用时，以本地完整归档作为长期证据；启用后须在远端到期前下载并校验导入，不把检查页面当作永久档案。
7. 上传全部附件并再次核对摘要，再发布 Release。安装说明须如实注明选择推荐环境时首次安装需要联网。

自动部署验证须覆盖环境复用/变化检测、切回推荐环境、升级/回退、损坏下载、兼容性失败、用户数据保护、自定义安装位置、共享组件及卸载边界。

人工验收至少包含：首次安装位置选择及取消；检测通过后的双选项弹窗；没有合格本地环境时的下载提示；已选环境失效后的确认与拒绝；从 Windows“已安装的应用”卸载并保留报告。每版检查旧报告/配置兼容性、升级操作、环境要求变化和实际已知问题。

## 发布说明

- 使用模板的二级标题，只固定“本次更新”和“校验”。先写相对上一发布版本最主要的实际产品变化，说明界面或操作如何改变；外部贡献注明贡献者及 PR。变化较多时再分类，测试、归档和流程调整放在产品变化之后，验证细节可折叠展示。
- 固定安装、环境和启动说明由 [README](../README.md) 维护；本版本改变相关要求时再写入发布说明。可选栏目无内容就省略，不填“无”。
- 有实际影响时增加“升级与兼容性”或“已知问题”，说明影响、必要操作或经验证的处理办法；同一事项不重复列入更新列表。
- 测试数和兼容性结论须有可靠记录，不补造历史验证、不粘贴完整日志、不累计历次通过数。只改变排版时不扩写或重新解释技术事实。
- “校验”逐行填写整个 ZIP 的 SHA-256 与准确附件名。已有上一发布版本时可附经核对的版本比较链接，两端使用实际 Tag。
- 发布前删除提示、占位符和空小节。正文只陈述本版本记录支持的事实。

已发布版本只修正文案排版、失效链接和明显笔误，不悄然改变行为描述。改变附件内容须递增版本号；历史补录明确标注，不追加当时没有保存的验证结论。

测试与人工验收仍需分别记录；发布模式不能代替联网部署、人工安装验收或 GitHub 分支规则。证据格式见[测试规范](testing.md)，本地 ZIP 和归档的保留、命名及 Git 范围见[本地数据规范](local-data.md)。
