# VMAF 的官方计算路径与适用边界

本软件使用 Netflix 官方 libvmaf，经 FFmpeg 官方 `libvmaf` 滤镜计算，不自行实现 VMAF 特征、预测或分数修正。“按官方执行”指采用明确版本的官方模型、官方默认评分行为与官方汇总，同时验证输入和保留证据；不表示本软件通过了认证，也不表示任意视频的分数都获得主观实验验证。

## 模型与观看条件

| 模型标识 | 官方观看条件 | 用途 |
| --- | --- | --- |
| `vmaf_v0.6.1`（默认） | 1080p HDTV，观看距离为屏幕高度的 3 倍（3H） | 保留既有官方 v0 基准 |
| `vmaf_4k_v0.6.1` | 2160p 4KTV，1.5H | 4K 对应的模型 |
| `vmaf_v0.6.1neg` | 1080p，3H | NEG：移除增强处理带来的收益，适合编码器比较 |

以上是官方仍提供的 v0 模型，不代表官方只有这些模型。官方已另行发布 v1 系列；本次保持既有运行时、默认模型和软件版本，不自动升级到 v1。模型代际和观看条件不同的分数不能直接混用。模型选择在质量对比、原生位深片段实验和任务计划中明确保存。

软件按输入原生栅格计算，不擅自缩放。输入分辨率不等于所选模型的显示分辨率时，报告说明该偏离；尺寸和色彩标签吻合也不构成感知适用性验证。未经验证的输入连相对比较的主观质量排序也不保证。若目标是某种显示条件，应明确准备已对齐、按目标显示条件处理的两路视频，并记录过程。官方示例中的缩放是评测条件的一部分，不能把原生栅格分数宣称为自动完成该条件的评分。

## 输入验证与 Full / Limited

| 检查或限制 | 核对依据与当前处理 |
| --- | --- |
| libvmaf 两路尺寸、像素格式 | FFmpeg 原生接口硬性要求，保留 |
| 原生格式能力 | 由各官方滤镜和实际编码器决定，不用 VMAF 格式限制 PSNR/SSIM |
| SDR 白名单、完整色彩标签 | 官方接口没有该要求，取消拦截并记录解释边界 |
| 原生 VMAF 必须逐行 | 官方接口没有该检查，取消拦截，保留隔行说明 |
| 跨位深、播放采样不能算 VMAF | 官方接口可接受明确准备后的同格式序列，取消跳过并记录处理 |
| 明确的两路色彩冲突 | 软件的直接比较策略，拒绝未解释的信号域混合，不宣称官方必然拒绝 |
| 帧数、时序、动态格式检查 | 软件用于确认对应关系和完整输出；时间容差不是 Netflix 标准 |
| 特定 BT.709 Limited 位深映射 | 显式转换模式的实现范围；不用于限制原生 Log/HDR/未知标签 |
| 试编码逐行、片段长度及任务点数 | 当前编码能力及资源范围；不称为质量指标的官方要求 |

- FFmpeg libvmaf 原生接口要求两路尺寸及像素格式一致。本软件进一步检查帧对应、明确的信号声明冲突和帧内格式变化；这些是直接比较的可复查规则，不是 Netflix 规定的通用时间容差或标签白名单。
- 本项目锁定的 FFmpeg libvmaf 支持平面 YUV 420 / 422 / 444、8 / 10 / 12 / 16-bit，直接交给官方实现。RGB、灰度、旧式 `yuvj*` 不在该 FFmpeg 滤镜的原生格式列表内；不通过隐式转换放行 VMAF。PSNR / SSIM 使用各自官方滤镜的原生格式能力，不再受 VMAF 的 YUV 格式列表限制；报告按实际格式提供 Y/U/V、R/G/B、灰度或透明分量。
- 同范围配对的 `pc`（Full）和 `tv`（Limited）均直接交给官方滤镜；不进行 Full→Limited 映射，不修改像素值，不通过强制覆盖标签放行。Full 与 Limited 混合输入仍被拒绝。
- libvmaf 的图片接口没有颜色范围参数，FFmpeg 滤镜直接复制解码样本；这说明官方实现可计算原生码值，不等于每个范围、色彩空间和内容类型都单独经过模型训练或主观验证。不同范围、位深、采样或色彩条件的绝对分数不直接比较。
- 不用 SDR、Log、PQ / HLG 或色彩标签白名单拦截 VMAF。传递函数、原色、矩阵、范围或色度位置未知时保留缺省值，报告记录哪一路缺失，不自动推断、补写或转换。未知不等于明确冲突，也不证明两路实际信号域一致；受控试编码的来源和处理记录可用于判断一致性，独立外部文件不能仅凭相同缺省标签得到这种保证。
- 两路明确且不同的范围、原色、传递函数、矩阵或色度位置仍拒绝直接评分。这是本软件避免未解释的信号域混合的策略；官方接口并非普遍拒绝这些标签。例如 FFmpeg libvmaf 对范围不同仅警告。软件不通过改标签或隐式色彩转换掩盖冲突。
- 原生比较的未知色度位置无需填写假设才能运算；已有显式用户确认入口仍可记录外部证据，只补充未知值，不覆盖明确声明。报告保留该假设，不声称软件验证了实际采样位置。
- 容器已有明确色度位置而解码帧未重复声明时，沿用轨道声明，不将缺省误判为冲突；例如 HEVC 422/444。帧与轨道均明确声明且位置不同时仍拒绝。缺省、`unknown` 和 `unspecified` 均表示未声明，不据此生成新的位置标签。
- 默认要求帧数及相对时间戳一致，随后以同一序号时间戳配对，避免时间基舍入选到邻帧。明确确认的帧序模式保留为用户承担对应关系假设的入口；不会自动回退。候选始终是滤镜第一路输入，参考始终是第二路。
- 原生隔行视频可以计算解码帧的 VMAF；不自动去隔行或按场评价。报告记录隔行输入及未确认的观看适用性。试编码仍只处理逐行片段，因为该编码路径尚未实现并验证隔行属性保持；这是编码流程的能力边界，不是 VMAF 接口限制。
- 显式 VFR↔CFR 播放采样和跨位深模式也可计算 VMAF。播放采样只评价记录的采样序列，不覆盖未采样画面；跨位深使用已有精确乘 4 的共同 10-bit 域。报告记录实际预处理和测量格式，不把这些结果称为帧率转换或位深转换的标准化观看质量。

Log、HDR、未知标签、隔行或模型显示条件偏离均不阻止数值运算，但报告明确说明当前 v0 模型的感知适用性未确认。软件不自动应用相机 LUT、调色、显示变换或色调映射。S-Log3 可能没有被 FFmpeg 识别为相应标准标签；未知标签不会被自动识别为 S-Log3。数值对照测试不能替代官方主观模型验证。

输入被支持不保证模型对所有失真都可靠。官方模型主要用于压缩和缩放相关失真；不得把分数当作色度损失、HDR 显示效果、帧率转换、任意处理失真或动态元数据的完整质量评价。同文件自比较也不要求恰好 100。

## 参数、汇总与报告

原生片段试编码直接从源文件编码候选，再将候选与同一源片段比较，不强制创建 FFV1。前置核验、编码及评分共用 `-ss` 准确定位、输入时长限制、`trim` 区间和首帧归零规则；禁止自动旋转和格式转换。按当前编码器实际声明的像素格式能力检查输入，再以 `-pix_fmt +原格式` 禁止回退。编码后核验像素格式、栅格、已声明的像素宽高比、明确色彩声明的冲突、帧数及时间关系。未知标签不生成替代声明，编码器或封装器出现缺省声明时也记录两路缺失信息。相同源文件的大小、身份或修改时间发生变化时终止任务。不把编码器或封装器的能力限制说成模型限制。

源文件可具有比 Matroska 更细的时间基。试编码记录输出时间基、相对时间戳实际偏差和容差；允许最多一个输出时间基刻度（不超过 1 ms）加 1 µs 的 FFprobe 日志舍入误差。两个独立舍入的 PTS 相减最多产生一个刻度的误差；若源帧间隔不足以区分该误差则拒绝评分。通过核验后仍按相同帧序号配对，不自动补帧、丢帧或按时间重采样。此规则只适用于由本任务从同一源片段生成的候选，不改变普通质量对比的 0.1 ms 默认容差。这是明确记录的容器精度处理，不是 Netflix 的通用时间容差标准。

独立的 8/10-bit 对照实验仍限于既有 420 BT.709 Limited 转换流程，并保留 FFV1 作为位深转换输入。该缓存必须先与实际源片段比较：每帧、每个 Y/U/V 分量的 PSNR 都为无穷大，即原生整数采样的均方误差为零，同时验证格式及帧对应关系；不通过则拒绝继续。不会使用 VMAF 自比较接近 100 作为像素一致性证明。此实验可选 VMAF，各组对照共同的 10-bit 无损参考；8-bit 候选先精确乘 4 后输入官方模型，报告同时保留源到共同参考的准备过程。该特定转换模式的 BT.709 Limited、逐行和已知采样位置条件属于其实现范围，不是原生指标或官方 VMAF 的通用限制。

计算显式指定所选官方 `model=version=…`、`pool=mean`、`n_subsample=1`、`n_threads=2` 和 JSON 日志。评分裁剪沿用官方模型默认行为，不启用分数变换，不使用自定义模型或调整特征权重。线程数是执行设置，不是模型或观看条件。

前置核验要求完整帧序相同；滤镜使用 `shortest=1:repeatlast=0` 防止补用末帧，随后再次验证日志帧数和连续帧索引。缺帧、非有限分数、越出本次 v0 默认裁剪范围的分数或损坏汇总均拒绝采纳。

VMAF 整体值直接取官方 JSON 的 `pooled_metrics.vmaf.mean`，不重新平均已舍入的逐帧值。保存官方最小值、最大值、均值和调和均值（日志提供时），主评分仍为官方默认算术均值；不按播放时长加权。逐帧日志与官方汇总相互校验时允许 JSON 小数舍入误差，不用该容差修正分数。

PSNR / SSIM 的整体值和各分量整体值直接采用 FFmpeg 官方滤镜在内部累计后打印的汇总，按其 6 位小数保存，并记录原始汇总文本。PSNR 官方内部先平均 MSE 再换算 dB，SSIM 内部逐帧等权平均；软件不从 2 位小数的 PSNR 或 6 位小数的 SSIM 逐帧日志重新生成整体值。汇总缺失、重复、异常或分量不完整时拒绝采纳。逐帧日志仍用于曲线、P05、最低帧和区间定位，这些附加统计受日志精度限制。新报告导入核验官方汇总与保存值一致；旧报告保留原值，不补造汇总或重新计算。

报告保存模型、模型观看条件、libvmaf 日志版本、实际测量输入条件、配对方式、预处理、标签缺失、感知解释边界、参数、官方汇总、完整原始日志和执行命令。VMAF 配置记录使用 `configurationVersion: 2` 区分新旧证据，并非软件版本升级。P05、最低帧和最差五个 1 秒区间是本软件用于定位复查的附加统计，不能称为官方 VMAF 整体评分。新报告导入时核验这些 VMAF 证据的一致性；旧配置及不含新增字段的历史报告仍可读取。

## 验证与官方依据

`test/vmaf.test.mjs` 用独立的官方 FFmpeg 命令（`PTS-STARTPTS`、候选/参考顺序）对照软件实际输出：Full/Limited × 420/422/444 × 8/10/12-bit、原生 16-bit、合成 Log/PQ/HLG 声明及未知标签、隔行解码帧、HD/4K/NEG 模型、正反参考方向、自比较、汇总和异常日志。另核验未知标签 422 10-bit x265 多 CRF 试编码、显式采样、共同位深域及 RGB/灰度 PSNR/SSIM 分量。合成声明用于接口回归，不是实际相机 S-Log3 或 HDR 的主观验证。浏览器与报告测试覆盖模型选择、实际任务、报告和任务计划往返。测试使用项目锁定的现有运行时，不构建安装包。
