# MediaScope 0.1.3-beta

Windows 本地媒体结构与质量分析工具。原生 Node.js + 浏览器 + FFmpeg/FFprobe，无 npm 依赖，媒体不上传。

## 使用与测试包

- **当前源码版**：双击 `start.cmd`，或 `npm start`，打开 http://127.0.0.1:4317 。需要 Node.js 22+ 和 FFmpeg/FFprobe；也可使用 FFMPEG_PATH / FFPROBE_PATH 指定程序。
- **当前轻量测试包**：[MediaScope-0.1.3-beta.zip](https://github.com/Gavin-530/MediaScope/releases/download/v0.1.3-beta/MediaScope-0.1.3-beta.zip)。包内保留版本号和逐文件 SHA-256 清单，不包含 Node.js、FFmpeg 或 FFprobe；换到其他设备前需安装这些依赖。
- 历史版本及其校验值见 [GitHub Releases](https://github.com/Gavin-530/MediaScope/releases)。已发布版本保持不可变；修复和功能调整递增前三段版本号，当前为 `0.1.3-beta`，只有需要同时区分同一源码版本的多个构建时才增加 `beta.1`、`beta.2`。
- 包内没有个人媒体、分析报告或测试生成文件。只有明确指定的正式版才构建包含运行环境的 Windows x64 完整便携包。
- 保持服务窗口运行，Ctrl+C 停止。通过 PORT 环境变量可改变端口。程序只监听本机回环地址，API 检查会话令牌与来源。

## 工作流程

### 文件分析

点击「选择文件」或粘贴本机绝对路径 → 读取信息 → 选择视频轨道 → 完整逐帧分析。Windows 文件选择器会直接返回本机路径，媒体内容不会上传。手动输入支持中文路径，并会清理复制时常见的成对引号、不可见方向字符和盘符全角冒号。

- 读取所有视频、音频、字幕、数据轨道，显示编码、像素格式、位深、色彩声明、章节与原始标签。
- **GOP 总览**：全片色带显示按随机访问/关键帧分段的显示帧区间，点击选择；支持上/下一 GOP、编号跳转。
- **帧带**：纵轴是解码器报告的包字节，按预测类型/特殊类型着色；顶部标出关键帧。点击帧查看 PTS、类型与码流包证据。列表可折叠，支持 CSV。
- **H.264**：从 NAL 类型区分 IDR 与 non-IDR，保留 recovery point 字段。
- **HEVC**：识别 IDR_W_RADL、IDR_N_LP、CRA、BLA、RADL、RASL、TRAIL、TSA、STSA 等 NAL 访问类型，保留时间层与 POC LSB。
- **AV1**：全流读取 OBU/帧头，编码顺序与显示顺序分开。列出 KEY、INTER、INTRA_ONLY、SWITCH、隐藏帧、SHOW_EXISTING 与冗余帧头，显示参考槽、刷新掩码、order hint、层编号、base_q_idx、film grain 等结构字段。显示已有帧会链接到已保存的编码事件；短参考信令按规范推导。OBU 负载字节不一定是完整图像字节数。不是像素块/变换系数解析器。
- **视频与每条音轨码率**：使用压缩包大小按绝对 PTS 的 1 秒窗口统计。缺 PTS 时回退 DTS，空秒填零；缺失时间戳的包单独计数。平均码率按包覆盖时长计算。首尾窗口可能不满 1 秒，负 PTS 的编码预卷也可能出现。
- 所有曲线可按钮缩放/平移、拖动框选、Ctrl+滚轮缩放、输入范围和双击全览。缩放只改变显示范围，不改变测量窗口。
- **体积分解**：每条轨道压缩包大小与文件占比。容器/未归属差额不假装是精确 box 大小。
- **元数据证据**：合并轨道与开头抽样中相同的附加数据，标明来源、重复次数，按需展开。明确区分标签声明与像素测量；抽样未发现不能证明全片不存在。

可勾选 **SI/TI 内容复杂度**：增加一次全片解码，测量空间细节与帧间变化，输出时域曲线、均值、P95 与最大值。TI 汇总排除首帧零值。峰值可能来自运动、剪辑、闪光或噪声，不自动命名为场景切换。SI/TI 不是剩余可压缩率，跨位深、分辨率、帧率、色彩范围比较须谨慎。HDR 在编码值域计算。

### 质量对比

指定参考源、候选文件及绝对视频轨道索引，确认相同剪辑。运行 PSNR / SSIM / VMAF。

- 严格校验分辨率、像素格式、色彩标签、帧数与相对时间戳（0.1 ms 容差）。然后按帧序号生成相同配对时间戳，防止舍入误差选到邻帧。不自动缩放、改采样、补帧、色调映射。禁用自动旋转，比较编码栅格。
- 默认仍为原生同格式比较。显式选择「8 ↔ 10-bit · BT.709 SDR 有限范围」时，仅放行相同采样格式、逐行、明确 BT.709 三项色彩标签和 `tv` 范围的 8/10-bit 配对；420/422 须已知且相同的色度位置。每帧仍按各自原格式验证，两路都禁止跨采样、跨色彩转换。12-bit、HDR、全范围或未知标签的跨位深配对拒绝运行。所选模式遇到同格式文件时仍执行原生比较。
- 跨位深比较依据 [ITU-R BT.709-6 §4.6](https://www.itu.int/rec/R-REC-BT.709-6-201506-I) 的码值关系，将 8-bit 的 Y/Cb/Cr 精确乘 4，保留 10-bit 原值：16→64、235→940、128→512、240→960。无抖动、无裁剪、无降位深。每次任务先在本机运行全码值（0–255、三分量、空间变化图样）自检，不符合精确乘 4 则拒绝评分。报告保存两路原格式、映射公式、目标域、自检和完整命令。
- 此模式测量两个文件的**总编码值差异**，提供 10-bit 域 PSNR/SSIM 与 Y/U/V 分量；PSNR 峰值取 1023，整体 MSE 按分量样本数加权。该峰值约定不等于亮度合法范围跨度 876，不应与其他峰值约定混用。跨位深 VMAF 暂不提供。转换依据标准码值关系，但本工具并非经过认证的标准化感知评测系统。仅凭最终两个文件无法拆分量化、抖动和压缩各自的损失，不生成假定量化基准，也不承诺色带或主观质量结论。
- 已验证原生平面 YUV 4:2:0 / 4:2:2 / 4:4:4、8 / 10 / 12-bit。PQ / HLG HDR、BT.709、BT.601 等相同色彩声明的视频可比较编码值；不推断未知色彩标签，不进行跨色彩空间转换。逐帧检查格式和色彩声明是否变化，发现变化则拒绝比较。报告记录比较域、位深、采样及色彩标签，并提供 Y / U / V 独立分量，避免色度损失被整体值掩盖。
- VMAF 固定记录 `vmaf_v0.6.1`，只接受明确 BT.709 SDR 有限范围，原生支持上述采样和位深。VMAF 不衡量色度损失，应结合 YUV 分量判断。选择多个指标时，不适用的 VMAF 会明确标注原因并跳过，保留 PSNR / SSIM；仅选择不适用的 VMAF 时拒绝运行。不是 HDR VMAF，也不是任意观看条件下的绝对质量保证。
- PSNR 在归一化 MSE 域汇总（受 FFmpeg 逐帧日志舍入精度限制），SSIM/VMAF 逐帧等权平均；提供最低值、P05、逐帧曲线及最差的五个 1 秒区间。SSIM 日志仅保留 6 位小数，极小差异可能显示为 1；判断码值完全相同时应结合 PSNR。VFR 不是时长加权。Infinity 以字符串保存。
- 单独比较视频包体积，避免多音轨差异污染视频压缩体积比较。参考源本身有损时，指标仅衡量相对该参考的变化。

### 可选短片段试编码

在「片段实验」选择起点、1–20 秒长度、编码器及 1–12 个 CRF 点。支持逗号列表和 `起点:终点:步长`，例如 `18:30:2`；x264/x265 允许 0–51 小数 CRF，libaom-av1 为 0–63 整数。x264/x265 可从 ultrafast 到 placebo 的 10 个 preset 中同时选择 1–4 项；AV1 可设置 cpu-used 0–8。默认保持 5 秒、x265 medium、CRF 20/26/32。一次最多运行 64 个 CRF × preset × 位深编码点。

1. 从原文件解码指定片段，保存 FFV1 无损像素参考（Matroska 保存色彩声明）。
2. 逐点真实试编码，仅处理选定的视频轨道；支持 4:2:0 8/10-bit 逐行视频。默认保持源位深。「8-bit 与 10-bit 对照」仅允许明确 BT.709 SDR 有限范围、逐行且明确色度位置的输入：8-bit 源精确乘 4 准备 10-bit 输入；10-bit 源按 `floor(code10 / 4)` 准备 8-bit 输入，无抖动，保留头部/脚部余量。截断是已记录的实验选择，不代表唯一标准量化方法。每次任务验证全 1024 个输入码值的降位深映射，或验证升位深后的像素完全相等。
3. 测量视频包字节、码率、PSNR/SSIM（原生模式可选 SDR VMAF）及本机编码秒数/fps。双位深各组均对照同一个 10-bit 无损参考，8-bit 输出精确乘 4 后评分，PSNR 峰值统一为 1023。采样、色彩声明、帧序和所选 preset 保持一致，输出位深逐点核实；不支持跨采样。额外报告编码前两种输入的差异，不能把基准分数从成片分数中直接相减，也不把升位深说成恢复原始细节。
4. 默认完成、失败或取消后清除临时参考和编码视频，保留报告及各点指标日志。可选择保留实验视频。原文件不改动。

结果按位深和 preset 使用独立曲线、共同坐标：CRF 对 PSNR、SSIM、码率和编码耗时；质量对视频体积、编码秒数或编码 fps。可选择某个编码点查看逐帧指标，旧报告缺少逐帧数据时会说明。无限值/缺失值不画为零，表格保留原值，连线只辅助观察实测点。

结果仅代表该片段、编码器及预设，**不外推全片大小，不将同 CRF 视为跨位深/预设的同等质量或码率**。编码速度含进程启动与 I/O，不含参考准备、量化转换和质量测量；各点顺序运行且仅测一次，受负载、缓存和温度影响。实验不保留音轨、字幕、Dolby Vision/HDR10+ 等动态元数据，也不评价其观看效果。HDR 可用原生位深模式，双位深实验暂不接受 HDR。单次参考原始像素预算限制为 8 GiB。

## 报告与资源边界

- 导出 JSON 包含工具版本、完整命令/工作目录、测量结果和警告；CSV 提供显示帧列表。可从页面「导入 JSON 报告」读取旧版/新版 JSON，无需重跑分析。
- 导入在浏览器本地读取（上限 256 MiB），无需原媒体文件；支持 MediaScope/0.1、0.2，拒绝未知版本和缺少必要结构的报告。导入与计算完成使用同一预览逻辑，保留数值精度、逐帧数据及复现证据。旧报告未保存的字段不会补造；缩放、分页和选中位置从默认视图开始。导入后仍可再次导出 JSON。
- 报告位于 `.mediascope/<任务编号>/report.json`。服务端完成后释放大结果对象，下载时从磁盘流式读取；三个页签在当前会话中各保留一份报告及图表交互状态；切换不重绘，后台计算完成只更新所属页签，不抢占当前查看页。仍然一次运行一个计算任务。
- 单次一个任务，可取消。显示帧/压缩包上限 500,000，AV1 编码事件上限 750,000。完整头解析可能较慢。多层 AV1 保留各层事件；涉及无法唯一映射的显示帧或缺少前置状态时明确标记，不伪造依赖。
- GOP 是显示帧区间视图，不能仅凭关键帧间隔判断是否存在跨 GOP 引用；不把 CRA 自动认定为闭合 GOP。未完整验证解码依赖图。
- 首版仍不提供精确剩余压缩率、设备兼容性保证、运动矢量/编码块深度解析、HDR 显示校准或通用播放器。
- 分享报告前检查其中的文件路径。私有报告不打入便携包。清理只针对工具生成的合成测试与打包暂存文件，保留用户报告。

## 开发与验证

`npm test` 会在 `test-work` 生成合成素材。测试覆盖中文路径、多音轨、H.264/HEVC/AV1、HDR、错位拒绝、IDR/CRA、AV1 隐藏/show-existing/参考槽、SI/TI、包字节汇总以及三种编码器的片段实验。测试用素材不是用户媒体。

`scripts/package-prerelease.ps1 -Version <预发布版本>` 在本地 `releases/` 目录生成不含运行时的轻量测试 ZIP；该目录中的 ZIP 不提交到 Git，公开下载包上传到 GitHub Releases。版本使用 `x.y.z-alpha`、`x.y.z-beta` 或 `x.y.z-rc`，确有多个构建时可增加 `.1`、`.2`。`scripts/package.ps1 -Version <正式版本> -Formal` 只用于明确指定的正式版，生成带运行环境的 Windows x64 便携 ZIP。两个脚本都不覆盖已有包。使用 `scripts/cleanup.ps1` 清理已验证的打包暂存和合成测试输出；它保留真实文件报告。

### 图表读法

- 默认以视频平均码率（Mbit/s）为横轴、质量指标为纵轴；同等质量下比较码率，同等码率下比较质量。编码成本图使用散点，避免把耗时顺序误读为参数连续变化。
- CRF 四图是参数扫描：每条线固定 preset 与位深，圆点为实测 CRF；连线仅辅助读图，不是拟合。同 CRF 不代表同质量或同码率。
- 逐帧叠加图固定 preset 和位深，勾选多个 CRF 并列比较；新实验保存参考帧的真实相对时间戳，旧报告使用从 0 开始的帧序号，不按平均帧率估算秒数。
- PSNR 单位 dB（汇总在 MSE 域）；SSIM 无量纲；VMAF 是指定模型分数。码率仅计视频包，1 Mbit/s = 10⁶ bit/s；1 KiB = 1024 B。
- 默认纵轴固定为该图全部数据范围，可主动切换局部缩放；纵轴可能不从零开始，各图范围独立，应读刻度而非仅比较视觉斜率。无限值和缺失值保留断点，密集时保留像素列内极值。
- 这些图用于客观测量探索，并非主观质量实验或统计显著性证明。耗时为本机单次测量，不提供误差条；科研报告还需规定测试集、参考与比较域、指标/模型版本、硬件和重复测量方法。
