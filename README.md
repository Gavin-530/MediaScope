# MediaScope

Windows 本地媒体结构与质量分析工具。原生 Node.js + 浏览器 + FFmpeg/FFprobe，无 npm 依赖，媒体不上传。

## 安装、更新与环境选项

- **首次安装可能需要联网**。Windows x64（Windows 10/11，PowerShell 5.1+）从 GitHub Release 下载对应版本的 Windows ZIP，完整解压后双击 `start.cmd` 自动安装并启动。首次先选择并确认实际安装文件夹，再检测电脑已有的 Node.js、FFmpeg、FFprobe：若三者通过版本、功能和实际运行验证，会弹窗让用户选择已有环境或推荐私有环境；若没有完整可用的已有环境，会告知原因并提示联网下载。完成后打开 http://127.0.0.1:4317 。
- 推荐环境是 MediaScope 私有 Node.js、FFmpeg、FFprobe，固定版本及 SHA-256 见 `runtime-lock.json`。选择推荐环境时**首次安装需要联网**，从 nodejs.org 和 GitHub 的构建下载服务下载约 230.1 MB 的两个上游 ZIP，校验后解压并保留上游许可证；用户现有 PATH 和全局程序不变。交互式安装会在当前用户注册安装位置和卸载入口。后续版本复用摘要相同、通过兼容性检查的组件，只下载清单中变化的部分；没有二进制差分下载。已安装且环境未损坏时启动不需要联网。
- 默认程序安装根目录为 `%LOCALAPPDATA%\MediaScope`，首次交互式安装可选择其他空的、可写文件夹；后续启动从当前用户的安装记录读取该位置。所选目录中的 `apps\<版本>` 是程序，`data` 是报告和任务文件。私有组件默认位于 `%LOCALAPPDATA%\MediaScope\runtimes\<组件摘要>`，即使程序选择安装到其他位置，开发版与用户版仍可按摘要复用组件。已安装旧版会沿用原位置及已有组件位置；自动化可通过 `MEDIASCOPE_HOME` 或 `-InstallRoot` 指定程序目录，通过 `MEDIASCOPE_RUNTIME_HOME` 或 `-RuntimeRoot` 指定组件根目录；`-NonInteractive` 不弹窗。安装不需要管理员权限。Fork/克隆源码后可直接双击源码目录的 `start.cmd`：它优先验证并使用电脑已有的 Node.js、FFmpeg、FFprobe；缺少完整可用的环境时会自动下载并校验私有运行时，首次需要联网，后续复用。源码直接从当前工作区运行，报告仍保留在 `.mediascope`；`npm start` 则仍要求自行准备 Node.js 与 FFmpeg/FFprobe。
- **卸载**：运行已安装版本中的 `Uninstall.cmd`，也可运行解压包中的同名入口；安装后亦可从 Windows“已安装的应用”打开卸载。卸载程序会检查安装记录、程序清单和运行锁，默认删除已安装的程序与临时文件，保留报告和私有运行时缓存；交互式卸载可分别选择删除报告、组件缓存。开发源码、外部 Node.js/FFmpeg 和历史测试归档不会被删除。卸载后若仍保留报告或组件，可在提示的安装根目录查看；再次运行旧解压包的 `start.cmd` 会重新安装。
- **换版本**：先停止服务，从 GitHub Release 下载目标版本的 ZIP，解压到单独文件夹，双击其中的 `start.cmd`。新包通过完整性与环境验证后安装到首次选择的软件位置并启动；不同版本的程序分开保存，报告继续使用原来的 `data`。从已安装程序目录运行 `start.cmd` 则启动当前选中的版本。相同版本若文件内容不同会拒绝覆盖。更新失败时，仍可运行原已安装程序的 `start.cmd`。程序不会自动查询 GitHub Release。开发者在源码目录运行 `start.cmd`，用 Git 切换源码版本。
- **从旧版安装方式转入**：完整解压新 ZIP，运行新包中的 `start.cmd`；已有安装位置和报告继续保留。旧源码目录中的 `.mediascope` 报告不会被搬动或删除，可在旧版导出 JSON，再在新版界面导入。
- **已有环境选项**：首次弹窗可选择电脑已有环境；高级用户也可使用下方显式路径命令。支持 Node.js 22/24 x64 与 FFmpeg/FFprobe 7+ 稳定版本；无法比较版本的 Git 开发快照不接受。首次、安装更新和手动检查时验证 `libvmaf`、`siti`、`psnr`、`ssim`、`zscale`、`trace_headers`、x264/x265/AV1/FFV1，并执行真实编码、解码、指标和 HTTP 启动测试。程序绝对路径、版本、SHA-256 和相邻 DLL 摘要记录在 `current.json`；源码版另保存按工作区区分的启动记录。已有成功记录的日常启动直接复用所选环境，不扫描程序/DLL、不计算组件摘要、不执行编解码测试，也不自动后台检测；安装版已验证的程序文件不逐次重验。环境损坏在实际使用时报错，不自动切换环境。记录缺失或损坏时按首次初始化处理；手动 `-Action Check` 始终完整检查。源码版可显式运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-source.ps1 -CheckEnvironment`：核对变化，媒体组件变化时先显示页面再后台完整验证，通过前禁止分析。源码切换版本或更换组件后需主动检查。
- 版本下载和校验值见 [GitHub Releases](https://github.com/Gavin-530/MediaScope/releases)。每版保留独立附件，不覆盖已发布文件。安装过程不迁移旧源码目录的 `.mediascope`；从该目录启动新版时执行近期记录保留规则，需要长期保存的报告请另行导出。
- 包内没有个人媒体、报告或测试生成文件。校验清单用于发现损坏，不能认证整包被恶意替换；请核对可信发布渠道公布的整个 ZIP 摘要。故障暂存与旧版默认保留，安装工具不会自动清理用户数据。
- **启动与退出**：双击 `start.cmd` 自动用 Edge（未安装时尝试 Chrome）打开独立应用窗口；首次宽、高各为当前显示器可用工作区的 75%，按系统缩放计算并居中显示，使用运行目录下专属的 `desktop-profile` 和访客会话，禁用浏览器同步及常规后台联网，不自动登录 Windows 账号；后续启动恢复上次窗口大小、位置和最大化状态，最小化不作为下次启动状态；显示器移除或可用区域变小时自动调整到可见区域。窗口退出、专用浏览器结束后清理该目录，主题偏好和窗口设置另存；窗口设置位于运行目录的 `desktop-window.json`。刷新不会停止服务；关闭应用窗口后自动取消未完成分析、清理后台检查并停止本次服务，控制台也随启动脚本退出。存在待运行或运行中任务时页面提供浏览器原生退出提示（需用户操作过页面），确认退出会停止任务，尚未运行的队列不会跨次启动恢复；近期记录默认保留最近 10 次、合计不超过 100 MB；可设置退出后清空，长期保存请导出 JSON。首次无可用环境时须先下载和验证，不能先提供完整页面。自动化的 `-NonInteractive` 不打开窗口；设置 `MEDIASCOPE_NO_BROWSER=1` 或直接 `npm start` 可使用手动网页模式，保持服务窗口运行，Ctrl+C 停止。通过 PORT 环境变量可改变端口。程序只监听本机回环地址，API 检查会话令牌与来源。

显式选择已有环境（路径含空格时保留引号）：

```powershell

```

首次选择已有环境不会下载私有运行时。所选程序必须可信；校验会执行这些程序。显式后台检查失败后保留上次成功记录，标记下次显式检查须完整验证；普通启动仍跳过检测。安装版手动检查继续沿用原有环境选择与失败询问流程。自动化或无人值守脚本可传入 `-NonInteractive`，跳过弹窗并按推荐私有环境安装；交互式启动只在用户明确选择后才切换。`npm start` 不再在启动前同步测试档案；测试入口也不自动同步历史档案，证据同步通过 `npm run evidence:sync` 显式执行。锁定来源与许可证见 `licenses/RUNTIME-SOURCES.md`。

## 工作流程

### 文件分析

点击「选择文件」或粘贴本机绝对路径 → 读取信息 → 选择视频轨道 → 完整逐帧分析。Windows 文件选择器会直接返回本机路径，媒体内容不会上传。手动输入支持中文路径，并会清理复制时常见的成对引号、不可见方向字符和盘符全角冒号。

- 读取所有视频、音频、字幕、数据轨道，显示编码、尺寸/SAR/旋转、像素格式描述、分量位深与报告位数、色彩标签、扫描方式、时间基与原始帧率、章节与标签。保留轨道报告值、派生解释及完整原始证据；基础读取不自动执行帧抽样，旧报告的样本仍可查看。字段依据与读取边界见[视频基础属性说明](docs/video-basic-properties.md)。
- **GOP 总览**：全片色带显示按随机访问/关键帧分段的显示帧区间，点击选择；支持上/下一 GOP、编号跳转。
- **视频大小主图 / 帧带**：复用同一组显示帧及其解码器报告的关联包大小，默认按真实呈现时间显示全片，时间来源为解码器报告／推定的显示时间，不按平均帧率估算。可切换到原有显示帧序号视图，GOP 导航、类型着色、关键帧标记、点击详情和逐帧 CSV 保留。时间视图用离散竖线，密集时同一像素列保留最大高度，不插值、不求和；单位自动选择且缩放时保持稳定。包与显示帧不保证一一对应，不能重复相加估算轨道体积。
- **音轨包大小时间分布**：完整文件分析额外保存每条音轨的解复用包，按起始 PTS 展示大小，保留整数时间戳、时间基和精确字节数。可点击查看 PTS/DTS/持续时间及原始字段，分页查看并导出逐包 CSV。缺 PTS 或无效时间基的记录仍在列表中保留，不回退 DTS；未知 duration 不妨碍已知 PTS 的包大小展示。包大小也受分包时长影响，不等于音频复杂度或瞬时传输速率。每条音轨最多保存 500,000 包，超限明确不提供逐包视图，既有码率及汇总继续保留。旧报告未保存逐包数据时不从窗口码率反推；质量对比和片段实验不额外保存这组记录。
- **H.264**：从 NAL 类型区分 IDR 与 non-IDR，保留 recovery point 字段。
- **HEVC**：识别 IDR_W_RADL、IDR_N_LP、CRA、BLA、RADL、RASL、TRAIL、TSA、STSA 等 NAL 访问类型，保留时间层与 POC LSB。
- **AV1**：全流读取 OBU/帧头，编码顺序与显示顺序分开。列出 KEY、INTER、INTRA_ONLY、SWITCH、隐藏帧、SHOW_EXISTING 与冗余帧头，显示参考槽、刷新掩码、order hint、层编号、base_q_idx、film grain 等结构字段。显示已有帧会链接到已保存的编码事件；短参考信令按规范推导。OBU 负载字节不一定是完整图像字节数。不是像素块/变换系数解析器。
- **视频与每条音轨区间平均码率**：计算前可选择 100 ms（默认）或 1 秒。按绝对 PTS 的对齐窗口 `[开始,结束)` 归属解复用包负载，每包计入一次；首尾截到轨道包时间跨度并除以实际时长，确认范围内的空区间为零。视频和每条音轨各自选择显示窗口，100 ms 结果可在前端聚合显示为 1 秒，合并整数包字节数和精确时长后计算，不平均已舍入的码率。视频 Mbit/s = 10⁶ bit/s，音频 kbit/s = 10³ bit/s。缺 PTS、未知/非正包持续时间或无效时间基准时曲线明确不可计算，不回退 DTS。此为媒体呈现时间上的包区间统计，不是实际网络速率，不扣除音频填充或负 PTS 预卷。旧报告继续按旧 1 秒口径显示。板块内全程平均值、试编码和体积比较沿用原有独立计算口径。详细规则见 [码率曲线测量规则](docs/bitrate-curve.md)。
- 所有曲线可按钮缩放/平移、拖动框选、Ctrl+滚轮缩放、输入范围和双击全览。缩放只改变显示范围，不改变测量窗口。
- **体积分解**：每条轨道压缩包大小与文件占比。容器/未归属差额不假装是精确 box 大小。
- **元数据证据**：保留轨道报告的附加数据，标明来源并按需展开；导入旧报告时继续合并和展示已有样本证据。明确区分标签声明与像素测量；未报告不证明全片不存在。

可勾选 **SI/TI 内容复杂度**：并行上限可选自动、1、2、4、6、8 路；自动默认最多请求 4 路，所有选项仍按资源预算降低。测量输出时域曲线、均值、P95 与最大值。TI 汇总排除首帧零值。峰值可能来自运动、剪辑、闪光或噪声，不自动命名为场景切换。SI/TI 不是剩余可压缩率，跨位深、分辨率、帧率、色彩范围比较须谨慎。HDR 在编码值域计算。

### 质量对比

指定参考源、候选文件及绝对视频轨道索引，确认相同剪辑。运行 PSNR / SSIM / VMAF。

- 默认严格校验分辨率、像素格式、明确的色彩声明冲突、帧数与相对时间戳（0.1 ms 容差），然后按帧序号生成相同配对时间戳，防止舍入误差选到邻帧。默认路径不自动缩放、改采样、补帧或色调映射；播放采样是另行显式选择的实验性模式。禁用自动旋转，比较编码栅格。
- 同一视频编码前后若时间基变化，可显式选择“按显示帧序号配对”并确认无丢帧、重复帧或重排。仍须通过两路帧数相同、各自时间戳递增及格式色彩校验；计算按解码显示帧序号配对，报告记录首次时间差、最大相对时间差和末帧时长差。帧数相同不能证明画面逐帧对应，因此该模式依赖用户确认，不自动回退启用。
- 独立的“VFR ↔ CFR 播放采样（实验性）”模式以已核验恒定帧率的一侧为时间网格，把两路首帧设为同一时刻；另一侧通过 FFmpeg `fps` 的 `round=up` 规则采样，不插帧。参考与候选角色保持不变，尤其不通过交换角色计算 VMAF。两侧均符合 CFR 时沿用候选侧网格。此模式要求用户确认共同起点、各路时间戳严格递增、CFR 时间戳与其帧率一致且被采样侧播放时段覆盖末个样本。报告标注网格所在侧、采样规则、CFR 网格偏差，导出的 JSON 保存逐网格帧的估计采样帧索引与重复/未采样数量；这些估计不是原编码器取帧映射的证据。结果属于自定义播放模型的画面差异，不是 ITU 标准化观看质量评分，也不覆盖网格之间短暂出现的画面。
- 文件未报告色度采样位置时，可显式启用“用户确认未知位置”，分别填写参考或候选视频经外部证据确认的位置并再次勾选确认。原生比较不要求补充未知值才能运行；可用外部证据补充未知值，不覆盖文件的明确声明，并逐帧拒绝明确冲突的声明。报告保留原始字段、采用值和“用户确认、未经软件验证”的标记。数值结果依赖该假设，工具不会自动推断或重采样。
- 默认仍为原生同格式比较。显式选择「8 ↔ 10-bit · BT.709 SDR 有限范围」时，仅放行相同采样格式、逐行、明确 BT.709 三项色彩标签和 `tv` 范围的 8/10-bit 配对；420/422 须已知且相同的色度位置。每帧仍按各自原格式验证，两路都禁止跨采样、跨色彩转换。12-bit、HDR、全范围或未知标签的跨位深配对拒绝运行。所选模式遇到同格式文件时仍执行原生比较。
- 跨位深比较依据 [ITU-R BT.709-6 §4.6](https://www.itu.int/rec/R-REC-BT.709-6-201506-I) 的码值关系，将 8-bit 的 Y/Cb/Cr 精确乘 4，保留 10-bit 原值：16→64、235→940、128→512、240→960。无抖动、无裁剪、无降位深。每次任务先在本机运行全码值（0–255、三分量、空间变化图样）自检，不符合精确乘 4 则拒绝评分。报告保存两路原格式、映射公式、目标域、自检和完整命令。
- 此模式测量两个文件的**总编码值差异**，提供 10-bit 域 PSNR/SSIM 与 Y/U/V 分量；PSNR 峰值取 1023，整体 MSE 按分量样本数加权。该峰值约定不等于亮度合法范围跨度 876，不应与其他峰值约定混用。跨位深可选 VMAF，记录共同的 10-bit 输入及精确乘 4 的预处理；不是位深转换的标准化观看质量评分。转换依据标准码值关系，但本工具并非经过认证的标准化感知评测系统。仅凭最终两个文件无法拆分量化、抖动和压缩各自的损失，不生成假定量化基准，也不承诺色带或主观质量结论。
- PSNR / SSIM 按各自 FFmpeg 官方滤镜支持的原生格式计算；已验证 YUV 420/422/444 的 8/10/12/16-bit，以及平面 RGB 和灰度代表格式。报告按实际格式保留 Y/U/V、R/G/B 或灰度分量。Log、HDR 及未知标签不阻止编码值域运算；未知信息保留并说明，不补写标签、不进行跨色彩空间转换。明确的标签冲突或帧内格式、已知色彩声明变化仍拒绝直接比较。
- VMAF 使用官方 libvmaf 和明确选择的官方 v0 模型：默认 `vmaf_v0.6.1`，可选 4K 或 NEG；不自动升级模型代际。按锁定 FFmpeg 的原生能力接受 YUV 420/422/444 的 8/10/12/16-bit，不因 SDR 白名单、Log/HDR、未知色彩标签或原生隔行帧而拒绝数值运算。Full/Full、Limited/Limited 均直接计算，不转换范围。显式跨位深及播放采样记录实际预处理。报告说明模型观看条件及未确认的感知适用性；尺寸和标签一致也不保证主观质量排序。仅在格式不受官方滤镜支持时跳过 VMAF；仅选该指标时明确报错。VMAF v0 不衡量色度损失。完整官方依据、软件的直接比较规则及复现说明见 [VMAF 计算说明](docs/vmaf.md)。
- PSNR / SSIM 的整体值及各分量整体值直接读取 FFmpeg 内部累计后输出的官方汇总，按其 6 位小数保存，并保留原始汇总文本；汇总缺失或异常时拒绝采纳，不从已舍入的逐帧分数反推。VMAF 直接采用官方 JSON 的算术均值。逐帧曲线、最低帧、P05 和最差的五个 1 秒区间来自逐帧日志，属于定位统计；PSNR 逐帧日志为 2 位小数，SSIM 为 6 位小数，不增加原始测量精度。SSIM 极小差异可能显示为 1；判断码值完全相同时应结合 PSNR。VFR 不是时长加权。Infinity 以字符串保存。旧报告保留原有数值，不补造官方汇总。
- 单独比较视频包体积，避免多音轨差异污染视频压缩体积比较。参考源本身有损时，指标仅衡量相对该参考的变化。

### 可选短片段试编码

在「片段实验」选择起点、1–20 秒长度、编码器及 1–12 个 CRF 点。支持逗号列表和 `起点:终点:步长`，例如 `18:30:2`；x264/x265 允许 0–51 小数 CRF，libaom-av1 为 0–63 整数。x264/x265 可从 ultrafast 到 placebo 的 10 个 preset 中同时选择 1–4 项；AV1 可设置 cpu-used 0–8。默认保持 5 秒、x265 medium、CRF 20/26/32。一次最多运行 64 个 CRF × preset × 位深编码点。

1. 默认直接读取源文件片段进行编码和指标比较，不创建 FFV1 参考缓存。前置解码只核验所选片段；编码和测量使用相同的准确定位、时间区间截取和首帧归零规则。源文件在任务期间发生变化时拒绝复用核验结果。
2. 逐点真实试编码，仅处理选定的视频轨道；原生模式读取逐行视频，并要求所选编码器实际支持源格式；逐行限制属于当前编码流程的能力边界，不是指标的官方要求。默认保持源像素格式、位深、分辨率、已声明的像素宽高比及色彩解释，不自动转为 420，不缩放、旋转或做色调映射。不复制源编码器的 profile、GOP 或压缩参数；由所选编码器生成适合该格式的码流。编码器不支持时明确失败，不降位深或改变采样。
3. 测量视频包字节、码率、PSNR/SSIM（可选 VMAF，保留模型适用性说明）及本机编码秒数/fps。输出格式、逐帧色彩声明、帧数和相对时间戳逐点核验。Matroska 的时间戳通常量化至 1 ms；仅试编码允许最多一个输出时间基刻度加 1 µs 日志舍入误差，并记录实际偏差，不补帧或丢帧。原生耗时包含源定位、解码、编码及 I/O，不含前置核验和质量测量；与旧版从缓存读取的耗时口径不同。
4. 「8-bit 与 10-bit 对照」保留单独的准备流程，仅支持 420、8/10-bit、明确 BT.709 SDR 有限范围、逐行且明确色度位置。源片段先写入 FFV1，并验证每帧 Y/U/V 均无像素误差及时间关系；8-bit 源精确乘 4 准备 10-bit 输入，10-bit 源按 `floor(code10 / 4)` 准备 8-bit 输入，无抖动，保留余量，并验证全码值映射。各组均对照同一 10-bit 参考，8-bit 输出精确乘 4 后评分，PSNR 峰值统一为 1023。截断是实验选择，不是 VMAF 官方要求；此模式可选 VMAF，也在共同 10-bit 域计算，记录参考准备和候选的位深映射。
5. 默认完成、失败或取消后清除本任务创建的临时视频，保留报告及各点指标日志。可选择保留候选视频；原生模式不会额外导出参考缓存。原文件不改动。

结果按位深和 preset 使用独立曲线、共同坐标：CRF 对 PSNR、SSIM、码率和编码耗时；质量对视频体积、编码秒数或编码 fps。可选择某个编码点查看逐帧指标，旧报告缺少逐帧数据时会说明。无限值/缺失值不画为零，表格保留原值，连线只辅助观察实测点。

结果仅代表该片段、编码器及预设，**不外推全片大小，不将同 CRF 视为跨位深/预设的同等质量或码率**。编码速度含进程启动与 I/O，不含参考准备、量化转换和质量测量；各点顺序运行且仅测一次，受负载、缓存和温度影响。实验不保留音轨、字幕、Dolby Vision/HDR10+ 等动态元数据，也不评价其观看效果。HDR 可用原生位深模式，双位深实验暂不接受 HDR。单次参考原始像素预算限制为 8.59 GB（8,589,934,592 B）。

## 报告与资源边界

- 所有新导出的 JSON 均使用 `MediaScope/0.3` 外层结构，分别包含 `results` 和 `plans` 数组。结果保存完整报告，计划保存待运行任务的原始参数与顺序；导出时分别选择当前单份报告、全部或勾选结果，以及全部、勾选或不包含计划。单份报告命名为 `MediaScope-<英文任务类型>-<素材名>-<本地时间>.json`，结果表、计划表和组合内容分别以 `MediaScope-queue-...json`、`MediaScope-plan-...json`、`MediaScope-bundle-...json` 命名；文件名只供识别，格式相同。CSV 仍可导出显示帧列表。
- 导入时分别勾选使用结果和计划，并设置各自的追加或替换方式。结果只进入结果列表，不加入运行队列，也不重新计算；计划进入待运行队列，默认保持暂停。兼容旧 `MediaScope/0.1`、`MediaScope/0.2` 单份报告、0.1.9 的三类 JSON 文件及先前生成的 `MediaScopePortable/1` 文件，按文件内部版本识别，原始报告数据不变。
- 导入在浏览器本地读取，所有新导出均限制在 256 MB以内，超限时需勾选较少结果。报告无需原媒体文件；计划运行仍要求所记路径下存在原媒体。导入保留报告数值精度、逐帧数据及复现证据；旧报告未保存的字段不会补造。缩放、分页和选中位置从默认视图开始。
- 交付版报告位于 `%LOCALAPPDATA%/MediaScope/data/<任务编号>/report.json`（源码开发版位于 `.mediascope`）。服务端完成后释放大结果对象，下载时从磁盘流式读取；近期任务默认跨重启保留最多 10 次、合计 100 MB，超限删除最旧记录；单份超限报告仅在当前会话可查看、导出，关闭后清理。启动恢复近期任务供查看、导出和重排队。“本地数据”显示占用，提供清空记录、清理缓存和退出后清空选项；软件退出后可手动删除整个运行目录。三个页签在当前会话中各保留一份报告及图表交互状态；切换不重绘，后台计算完成只更新所属页签，不抢占当前查看页。仍然一次运行一个计算任务。
- 队列一次运行一个任务，可暂停后续任务、取消当前任务或重新排队失败任务。显示帧/压缩包上限 500,000，AV1 编码事件上限 750,000。完整头解析可能较慢。多层 AV1 保留各层事件；涉及无法唯一映射的显示帧或缺少前置状态时明确标记，不伪造依赖。
- 运行卡片显示当前阶段、阶段序号、已运行时间和实时处理量；帧数、包数、编码点等只采用进程实际产出的计数。只有总量已经由前序扫描确定时才显示本阶段百分比，否则明确标为“总量待核验”。百分比不用于推算剩余时间；并行的包统计与码流头解析分别列出，不合并成虚假的单一完成率。
- GOP 是显示帧区间视图，不能仅凭关键帧间隔判断是否存在跨 GOP 引用；不把 CRA 自动认定为闭合 GOP。未完整验证解码依赖图。
- 不提供精确剩余压缩率、设备兼容性保证、运动矢量/编码块深度解析、HDR 显示校准或通用播放器。
- 分享报告前检查其中的文件路径。私有报告不打入便携包。清理只针对工具生成的合成测试与打包暂存文件，保留用户报告。

## 计算与图表说明

### 图表读法

- 默认以视频平均码率（按整组数值自动选择十进制单位）为横轴、质量指标为纵轴；同等质量下比较码率，同等码率下比较质量。编码成本图使用散点，避免把耗时顺序误读为参数连续变化。
- CRF 四图是参数扫描：每条线固定 preset 与位深，圆点为实测 CRF；连线仅辅助读图，不是拟合。同 CRF 不代表同质量或同码率。
- 逐帧叠加图固定 preset 和位深，勾选多个 CRF 并列比较；新实验保存参考帧的真实相对时间戳，旧报告使用从 0 开始的帧序号，不按平均帧率估算秒数。
- PSNR 单位 dB（汇总在 MSE 域）；SSIM 无量纲；VMAF 是指定模型分数。码率仅计视频包，1 Mbit/s = 10⁶ bit/s；1 kB = 1000 B；容量与码率按数值自动选择十进制单位，图表按整组数据选择同一单位且缩放时保持稳定；底层字节数与报告字段不变；近期记录和报告导入导出上限分别按 100 MB、256 MB 判断。
- 默认纵轴固定为该图全部数据范围，可主动切换局部缩放；纵轴可能不从零开始，各图范围独立，应读刻度而非仅比较视觉斜率。无限值和缺失值保留断点，密集时保留像素列内极值。
- 这些图用于客观测量探索，并非主观质量实验或统计显著性证明。耗时为本机单次测量，不提供误差条；科研报告还需规定测试集、参考与比较域、指标/模型版本、硬件和重复测量方法。

### 计算流程

- PSNR / SSIM / VMAF 在同一进程共享两路解码，保留原有逐帧校验、位深映射、时间戳配对、模型和汇总口径。不会抽帧、缩放或更换编码器。
- 实验内仅复用任务自己生成的固定参考的探测与逐帧校验；检查文件标识、大小与修改时间等信息，变化时拒绝继续。候选仍逐个完整检查，编码仍串行计时。
- 报告记录 timing（计算耗时及分析阶段耗时）和 commands 中每个子进程的 elapsedSeconds / exitCode，不含报告保存与浏览器渲染时间。报告 schema 保持 MediaScope/0.2，旧报告仍可读取。
- 兼容诊断时可在启动服务前设置 MEDIASCOPE_SEPARATE_METRICS=1，使用逐指标独立解码路径；默认共享解码。不自动重试失败的评分。
- GOP 头解析、VMAF 线程数与映射自检保持原路径；共享解码主要减少质量比较及实验的重复计算，不承诺全片分析已有显著加速。

### SI/TI 计算设备

默认 CPU，可选 GPU（OpenCL）。GPU 路径保持 FFmpeg 软件解码，每帧原生亮度平面无缩放、无抽帧上传 GPU；在 GPU 上完成亮度范围映射、Sobel、相邻帧差和两遍总体方差计算。当前仅支持 Windows、具备 `cl_khr_fp64` 的 OpenCL GPU，自动选择首个符合条件的设备。驱动需提供 OpenCL；不安装 CUDA/Python 依赖。Windows PowerShell 在进程内编译随源码附带的 C# 桥接代码，OpenCL 驱动编译计算内核，不生成新的软件发行包。

选择 GPU 时检测设备并执行独立标量参考自检；每个 GPU 任务重新自检，覆盖 8/10-bit、全/有限范围、越界裁剪、首帧与跨工作组归约。自检误差限为绝对 `0.0005` 加相对 `0.000002 × |参考值|`。真实媒体回归另与 FFmpeg CPU 逐帧对照；两位小数输出的允许绝对差为 `0.01`。这不是逐位相同承诺，也不是 P.910 合规认证。每帧格式、范围、时间戳、总帧数及首帧 TI 会检查；GPU 失败丢弃整次 GPU 结果，回退 CPU，取消不回退。

报告 `content.execution` 保存请求/实际设备、GPU 名称、驱动、后端、算法版本、数值自检与精度，失败时保存 `gpuFallbackReason`；`commands` 保存软件解码与 GPU 子进程耗时。GPU 仍有启动、传输与解码开销，短片可能更慢，不承诺加速倍数。支持原生 YUV 420/422 8/10-bit；444 等官方 CPU siti 不支持的格式明确跳过。

CPU/GPU 均沿用 FFmpeg siti 口径：有限范围先按整数规则扩展到全范围并裁剪越界值，未声明范围按有限范围；8/10-bit 不归一到共同尺度。SI 排除一圈边界，TI 使用全亮度平面；首帧 TI 为零且不纳入汇总。逐帧输出保留两位小数，汇总从这些值计算，VFR 均值按帧计而非按播放时长加权。当前尚未完整实现新版 ITU-T P.910 的亮度域转换等流程，CPU/GPU 均不能宣称完整符合新版标准。HDR 未转换到感知亮度域；应在相同分辨率、帧率、位深、范围和传递函数下比较。[FFmpeg 算法依据](https://www.ffmpeg.org/doxygen/8.1/vf__siti_8c_source.html)。

#### CPU 帧级并行

保持原版 FFmpeg siti 的逐帧算法、像素格式、时间戳与汇总顺序。各进程从头解码，按显示帧序号选取连续区间；非首段包含一帧前置重叠，计算后丢弃该重叠帧。合并检查总帧数、分段帧数和重叠帧时间戳/SI；失败回退串行，取消任务不重试。报告 content.execution 记录执行方式、并发数和回退原因，命令日志保留具体参数。

默认最多 4 路，按 CPU、可用内存及帧数限制，短片/未知帧数保持串行。环境变量 MEDIASCOPE_SITI_WORKERS=1 可强制串行，2–8 设置并发上限。并行会增加重复解码、内存及 I/O，实际加速取决于素材和硬件。该优化保持现有 FFmpeg 编码值域计算口径，不等于新增完整 P.910 合规认证；HDR 限制不变。

### 帧结构与 GOP

完整分析的显示帧扫描显式使用 FFprobe 软件解码线程，默认取本机逻辑处理器数与 12 的较小值。扫描完成后，并行执行全部轨道包统计和 NAL / OBU 码流头解析；三个阶段继续使用原有完整命令、解析规则和结果映射，不抽帧、不分段解析 GOP，也不把关键帧标记替代为 IDR / CRA 判断。所有阶段完成后才映射显示帧与码流事件，SI/TI 随后单独运行，不与这组任务叠加并发。

报告 `timing.decodeThreads` 记录帧扫描线程数，`timing.stages[].concurrentGroup` 标记重叠执行的阶段，其耗时不能相加。诊断兼容性时可在启动前设置 `MEDIASCOPE_DECODE_THREADS=1` 强制单线程解码，并用 `MEDIASCOPE_SEQUENTIAL_ANALYSIS=1` 恢复包统计与码流头解析的原顺序路径；所有路径使用相同计算函数和输出结构。

### 任务队列

文件分析、参考质量比较、片段率失真实验支持混合排队。在各功能中选择文件并设置参数后点击“加入队列”，重复添加，再点击“开始 / 继续队列”。完整分析可直接加入队列；未读取轨道信息时自动选择第一个视频轨道，需指定其他轨道时先读取信息。每项任务保存添加时的参数，后续修改表单不影响已排队任务。

队列顺序执行，运行或暂停期间均可继续添加。“读取信息”只做文件预览，不占队列项；完整分析在队列中只占一项，内部阶段在进度区显示。暂停后续任务不会中断当前任务；取消当前项或某项失败后会继续下一项，取消的任务直接移除，不进入“已结束任务”；已完成或失败的任务可从该列表重新排队，从头运行。待运行任务、已结束任务和结果列表均提供单项移除及清空入口；移除已完成任务会同时移除对应结果和本地报告记录，正在导出的报告待导出结束后清理。清空待运行任务不打断当前任务，原媒体和另存的实验视频不受影响。每项完成后均可从队列查看报告并导出 JSON。结果列表可导出全部或勾选的已完成报告；队列内等待的任务可勾选导出为计划表。原运行按钮会提交任务并开始队列。刷新网页可恢复队列；当前队列仅在服务运行期间保留，重启服务后可导入已保存的计划表，近期已结束任务按前述数量与容量限制保存，并在重启后恢复查看；长期保存请导出 JSON。
